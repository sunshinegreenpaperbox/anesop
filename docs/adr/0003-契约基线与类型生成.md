# ADR-0003 契约基线与类型生成

- 状态：已接受
- 日期：2026-11-12
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策）
- 关联：S0-05 / 方案书 §3.4/§3.5/§3.9 / AGENTS「契约优先与数据变更」

## 背景与约束

S0-05 要求：`packages/contracts/openapi/` 下 auth、patient、scheduling、anesthesia
四域 OpenAPI 3.1 骨架；spectral 规则；TS/Java 类型生成脚本；oasdiff 兼容检查；
验收"spectral 通过、生成物可编译、破坏性变更能被拦下、契约与数据字典初稿一致"。
约束：字段不得臆造（H-04），必须有方案书依据；写域不含 `apps/` 与根 `pom.xml`；
无 Docker；依赖必须在 allowlist 白名单内。方案未规定版本号、路径前缀、工具选型细节。

## 决策

1. **契约形态**：4 份 OpenAPI **3.1.0**，`info.version=0.1.0`，统一 `servers` 为
   `https://anesop.local/api`，路径前缀 `/v1`，全局 `bearerAuth`；共享组件
   `Error`/`PageMeta`/`AuditFields`/`IdResponse`；每个 operation 有 operationId、tags、
   中文描述、2xx schema、401/403/404/409、**SYNTHETIC** 示例。合计 22 path / 26 operation。
   字段依据 §2.4.1–§2.4.3、§3.4.2、§3.5.3、§3.9.2/§3.9.5、§2.7.1；不确定处标注
   【待确认】（CA 签名字段、会话 TTL/双因素、排程资质冲突字段、波形方案、麻精双人核对
   字段名、gender/birthDate 口径等），未臆造外部系统接口。
2. **规则与门禁**：`.spectral.yaml` extends `spectral:oas` + 自定义
   `rules/error-responses.js`；`--fail-severity=error`；当前 **0 error / 0 warning**。
   规则至少覆盖 operationId、tags、示例有效性、https server、错误响应、安全方案。
3. **SSR 兼容检查**：`packages/contracts/openapi/baseline/` 保存已评审基线快照；
   `scripts/contract-check.sh` 先 spectral lint，再以 **@oasdiff-js/oasdiff-js 1.0.0**
   （Apache-2.0，内含 oasdiff 1.15.0）做 baseline→当前 的破坏性变更检测，失败非 0。
   **不采用 openapi-diff 0.24.1**（不支持 OpenAPI 3.1）。基线只在人工评审通过后复制
   更新，脚本不自动改基线；破坏性变更流程写入 `docs/api/README.md`。
4. **TS 类型生成**：`openapi-typescript 7.13.0`（MIT）生成
   `packages/contracts/generated/typescript/*.d.ts`（首行 `DO NOT EDIT — generated`），
   4 份已提交；`pnpm exec tsc --noEmit --strict` 校验可编译。
5. **Java 类型生成：延后到 S0-07（已登记遗留）**。理由：Java codegen 需要新增 Maven
   模块并改根 `pom.xml`（超出本任务写域），且与模块边界/序列化库选型耦合；一期采用
   "springdoc 从实现导出 OpenAPI → 与 baseline 对比"的契约漂移检查，Java DTO 以模块内
   手写/生成混合方式在 S0-07 定案。**S0-07 必须补 `scripts/gen-contracts.sh --java` 与
   可编译校验，否则 M1 退出准则"契约生成类型可用"不满足。** 本条为已知缺口，已在
   STATUS/PROJECT_STATE 登记。
6. **契约检查进本地门禁**：`scripts/check.sh` 第 6 步改为调用
   `scripts/contract-check.sh`（无契约时跳过），失败即红，不用 `|| true`。
7. **供应链**：`@stoplight/spectral-cli` 的遥测依赖 `@scarf/scarf` 的 postinstall 在
   pnpm 11 严格模式下会使 frozen install 失败；在 `pnpm-workspace.yaml` 显式
   `allowBuilds: '@scarf/scarf': false` 关闭其安装脚本（无功能作用、纯遥测），
   不引入新依赖。该改动记录于本 ADR 与 allowlist。
8. **数据字典初稿**：`docs/data-dictionary/core-entities.md` 覆盖 M0/M1/M2 核心实体，
   与契约字段同名同义；标注"初稿，随迁移/契约演进"。

## 评审修复（2026-11-12，独立 review 后）

独立评审给出 2 项 blocking，已修复并复验：
1. **错误响应不完整 + 规则不校验语义**：全部 4 域增加共享 `BadRequest`(400)/
   `UnprocessableEntity`(422)；13 个带 requestBody 的 operation 声明 400；404 只用于
   含路径参数的单资源 operation（14 个），409 只用于状态变更 operation（9 个）；
   auth 的 login/refresh/logout 清理无语义的 404/409（logout 改 204）。
   `rules/error-responses.js` 重写：4xx/5xx 必须 `$ref` 到共享响应组件且状态码与组件名
   匹配；需认证必有 403（logout 例外）；有请求体必有 400；含路径参数必有 404；
   无路径参数禁 404、无请求体禁 409。
2. **锁单三方核查不可判定**：新增 `ThreeWayCheck`（timeOutAt/By、signOutAt/By、
   specimenChecked/implantChecked 全必填）+ `UpsertThreeWayCheckRequest`；新增
   `GET/POST /v1/anesthesia/records/{recordId}/three-way-checks`；记录单增加只读摘要
   字段；锁单 409 描述引用该校验。
3. **建议项落地**：contract-check 增加第 3 步"生成物漂移校验"（重生成后 git diff）；
   `idCardMasked` 改为前 3 + 11×`*` + 后 4（不含出生日期段），列表接口改用
   `PatientSummary`（无 birthDate / 无住院号明文，含 `inpatientNoMasked`），
   详情 `inpatientNo` 标 `x-restricted`；破坏性分类与 oasdiff 实际行为对齐；
   越权语义写死（集合越权 403 / 单对象越界 404）；DASI 去掉硬编码 `maximum:10`
   并标【待临床确认】；角色/权限码定稿回写列为 S0-07 待办。
4. **契约版本**：`info.version` 0.1.0 → **0.2.0**（新增三方核查接口属向后兼容 minor），
   baseline 按"人工评审通过后复制并同 PR 说明"更新为 0.2.0；当前 **23 path / 28
   operation**（auth 5/5、patient 6/6、scheduling 6/7、anesthesia 6/10），
   错误码分布 200×24、201×4、204×1、400×13、401×28、403×25、404×14、409×9、422×5。
5. 复验：spectral `--fail-severity=warn` 0 结果；contract-check lint/breaking/drift
   全 PASS；漂移与缺 400 两个变体均实测失败后恢复。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| openapi-diff 做兼容检查 | 0.24.1 不支持 OpenAPI 3.1，无法解析本契约 |
| 立即生成 Java DTO 并建 Maven 模块 | 需改根 pom + 新增模块，超 S0-05 写域，且 codegen 风格需与 S0-07 模块边界一起定 |
| 契约用 OpenAPI 3.0.3 | 方案与 AGENTS 锁定 3.1（springdoc 2.x 支持 3.1） |
| 基线自动覆盖为当前版本 | 会让破坏性变更"自动通过"，失去门禁意义 |
| spectral 用 `--fail-severity=warning` | 骨架阶段会产生大量风格噪声，先只阻断 error |

## 后果（正面/负面/代价）

- 正面：四域契约与共享错误/分页/审计模型一次成型；lint + 破坏性检查可重复执行；
  TS 类型可直接被 S0-08 前端引用；数据字典有初稿；供应链遥测被显式关闭。
- 负面：**Java 类型生成缺失**（S0-07 补齐，M1 前必须解决）；契约字段存在【待确认】项，
  进入 M1/M2 后需临床顾问/接口方确认；baseline 需人工维护（评审后复制）。
- 代价：pnpm-lock 增约 2.2k 行；spectral/oasdiff 依赖纳入 allowlist；每次契约变更需
  同步 baseline 与 TS 生成物（否则 contract-check 报告差异）。
- 后续：S0-07 补 Java 生成脚本与编译校验、auth 实现按契约落地；S0-08 前端从
  `@anesop/contracts` 引用生成类型；M2 起契约冻结后仅阻断缺陷可改。
