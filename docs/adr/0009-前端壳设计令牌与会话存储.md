# ADR-0009 前端壳、设计令牌与会话存储

- 状态：已接受

- 关联：S0-08 / AGENTS 前端技术栈 / auth.yaml 0.3.0 / ADR-0007 / ADR-0008

## 背景与约束

S0-08 要求登录页、主布局、路由与权限菜单、请求封装（token 刷新）、错误处理、设计令牌
（色板/字号/间距），验收"登录后进入首页；无权限菜单不显示；接口 401 自动跳登录；
`pnpm build` 通过"。约束：后端无 CORS 配置（同源假设）、前端技术栈锁定
Vue 3.5 + TS 5.6 + Element Plus 2.9.x + Pinia 3 + Router 4 + Vite 6 + ECharts 5.5.x；
无 UI/UX 设计稿（Q-12 未确认）；不得引入未审批依赖。

## 决策

1. **设计令牌独立包 `packages/ui`**（`@anesop/ui`）：CSS 变量（品牌/语义色、字号阶梯、
   间距、圆角、阴影、z-index、中文字体回退）+ TS 常量 + Element Plus 主题变量覆盖
   （`--el-color-primary` 等）。页面禁止硬编码颜色/字号，统一引用令牌；无 UI 稿阶段以
   保守医疗后台配色为准（蓝灰主色、低饱和背景、强对比文本）。
2. **依赖**：Element Plus 2.9.11（MIT，精确版本）；不引入 axios（原生 fetch 封装，避免
   多一层依赖与体积）；不引入图标库（菜单/操作图标用内联 SVG）；**ECharts 推迟到 M8**
   再引入（仅图表页面需要）。
3. **会话与令牌存储**：access token 存内存 + sessionStorage，refresh token 存
   sessionStorage；刷新页面后由 `/v1/auth/me` 重新校验（快照不替代服务端校验）。已知
   XSS 风险：M1 改为 httpOnly Cookie（需后端 CSRF/同源策略配套）+ CSP，已登记
   `docs/ui/README.md` 与 M1 待办。契约返回 token 于响应体，暂不改契约。
4. **请求封装**：`apps/web/src/api/http.ts` 基于 fetch——自动 `Authorization: Bearer`、
   `X-Trace-Id` 透传/生成、15s 超时、契约 `Error` 解析为 `ApiError`（code/message/
   traceId/details），页面按 code 分支、展示 message+traceId；401 时**单飞 refresh**（并发
   401 只刷新一次）并重放原请求一次，刷新失败清会话跳登录。
5. **路由与权限**：`routes.ts` + 守卫——无 token → `/login`；有 token 首次必拉
   `/v1/auth/me`；`meta.permissions`（OR 语义）不足 → `/403?from=`；`mustChangePassword`
   → 改密页（后端亦有 Filter 强制，双重保障）；菜单由 `navigation.ts` 单源生成并按权限
   过滤，避免路由与菜单漂移。
6. **本地联调**：Vite dev `/api` 代理到 `http://localhost:8080`（去掉 `/api` 前缀），生产
   由 nginx `/api/` 反代，避免 CORS 配置；后端未加 CORS 是刻意保持最小攻击面。
7. **页面交付**：登录、改密、会话管理、403、404、首页（角色/权限概览、系统状态卡片）、
   主布局（侧边菜单/顶栏/面包屑/响应式 1366/1920/窄屏收起）。m1–m8 保持占位。
8. **测试**：Vitest 32 个用例（守卫、菜单过滤、401 单飞刷新重放、登录成功/失败/空值、
   改密强度、布局断点、会话 403）；覆盖率行 88.3%/分支 80.2%（阈值 70/55）；
   Playwright 3 条壳冒烟。**真实联调**（嵌入式 PG + api-bootstrap jar + Vite）验证
   登录→改密→新口令→旧口令 401 与 401→refresh→重放链路。
9. **构建与体积**：Element Plus 全量引入导致 JS 844 kB（gzip 273 kB）>500kB 警告；
   M1 改为按需引入 + 路由懒加载 + 分包（已登记优化项），当前骨架阶段接受。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 引入 axios | 原生 fetch 足够（拦截/刷新逻辑自持），少一个依赖 |
| token 存 localStorage | 与 sessionStorage 同样受 XSS 影响；会话级存储攻击窗口更小，且刷新由 /me 校验 |
| 现在改 httpOnly Cookie | 需后端 CSRF/同源配套与契约调整，M1 统一做 |
| 立即引入 ECharts/图标库 | 骨架无图表页面，按需引入避免包体与依赖膨胀 |
| 后端加 CORS | 生产同源（nginx），dev 用 Vite proxy 即可；减少 CORS 误配风险 |
| 自建组件库 | 表单密集页面用 Element Plus 足够，AGENTS 要求不自建组件库 |

## 后果（正面/负面/代价）

- 正面：登录→首页→权限菜单→401 刷新→403 全链路可运行；设计令牌统一；请求/错误处理
  契约化；32 个前端测试 + 真实联调；Element Plus 主题可换。
- 负面：sessionStorage 存 token 的 XSS 风险（M1）；首包偏大（M1 优化）；登录提交 E2E
  留 M1；无 UI 稿导致视觉为工程默认；国际化、数据范围选择器、强制下线留 M1；ECharts M8。
- 代价：新增 element-plus 依赖与约 360 kB CSS；`packages/ui` 增加一个 workspace 包；
  前端测试与 E2E 纳入 check.sh（总门禁约 6–8 分钟）。
- 解除条件：UI/UX 稿（Q-12）→ 视觉细化；M1 完成 Cookie 会话与包体优化；M8 引入 ECharts。
