## 背景与约束

M5-M18-01 交付实时态势与当日 KPI 看板。方案书要求“实时手术态势、临床风险、资源态势、
运营 KPI、大屏与移动摘要”，并明确“驾驶舱只读，不提供业务写操作；指标口径与 M6/M7 同源，
不另建口径；实时数据延迟超过 2 分钟须标注”。约束有四条：

1. 统计单元分散在 M1 术间/排程台次、M2 麻醉记录单/术中告警/设备登记，M4 报表与排程分析
   已各自冻结口径（report-1.0.0、analytics-1.0.0），驾驶舱不得另立一套；
2. AGENTS 禁止跨模块访问对方 Mapper/数据表，也禁止 m5 反向依赖 m1-api/m2-api 形成环；
3. V26 限定为 **data-only** 迁移（只加权限点，无 DDL），不能新建看板结果表或物化视图；
4. 看板是高频读取（10s 轮询）：既不能把审计刷成噪声，也不能因为聚合而拖慢临床写入路径。

## 决策

1. **刷新机制：10s 前端轮询，后端无状态**。不使用 SSE/WebSocket：
   - 看板为只读聚合，单次请求是几条索引扫描 + 应用内聚合（本机实测见
     `docs/modules/m5/README.md` §性能），10s 轮询的资源开销远低于长连接与断线重连治理；
   - Spring `SseEmitter` 需要连接池、心跳、超时与多实例广播治理，且前端需 `EventSource`
     与重连状态机；本任务明确“无新依赖优先轮询，SSE 作为可选”，故不引入；
   - 轮询间隔与暂停由前端控制（`REFRESH_INTERVAL_MS = 10_000`），服务端每次请求独立计算，
     不做会话级缓存，也不保证两次请求之间数据连续（看板语义是“快照”）。
2. **时区与窗口**：所有“当日”按 `Asia/Shanghai` 自然日 `[00:00, 次日 00:00)`；实时态势的
   台次/告警窗口为 `[00:00, now]`，KPI 为整日（`date` 缺省服务端当日，允许
   `[today-366, today+31]`，超出 400）。
3. **台次口径复用 report-1.0.0**：`deleted=false`；非取消台次要求 `status ≠ CANCELLED`；
   按 `start_at` 本地日期归集，跨日只计首日；取消率分母含取消（与 analytics-1.0.0 一致）。
4. **已开始/已完成**：已开始 = 麻醉记录单 `started_at` 非空 或 台次
   `IN_PROGRESS`/`COMPLETED`；已完成 = 记录单 `ended_at` 非空 或 台次 `COMPLETED`；
   只统计非取消台次。
5. **准点率**：每术间当日**计划开始最早台次**为“首台”；首台取消/未开始/缺实际开始 →
   该术间-日不纳入评估（不拿第二台顶替，同 analytics-1.0.0）；判定阈值为
   `|实际开始 − 计划开始| ≤ 15 分钟`（`anesop.m5.dashboard.on-time-threshold-minutes`）。
   **实际开始优先取麻醉记录单 `started_at`，缺失回退台次 `updated_at`【待确认】**——
   后者是 M1 在“实际开台时间”尚无写入路径时的近似（ADR-0015 Q-1），驾驶舱优先用更真实的
   记录单时间，回退路径保证不把缺数据的术间-日误判为准点。
6. **利用率**：`Σ 非取消台次与当日窗口重叠分钟 / (可见术间数 × 每术间每日可用分钟)`；
   可用分钟默认 **600**（`room-daily-available-minutes`，取 ADR-0015 的同一默认值），
   计划 vs 实际占用口径 **【待确认】**（ADR-0015 Q-3）；分母为 0 时返回 0，允许 > 1。
7. **平均麻醉时长**：`Σ floor((ended_at − started_at)/60s) / 有可用时长台次数`，2 位小数；
   无记录单/未结束计入 `unrecordedCaseCount`，不参与分母（同 report-1.0.0）。
8. **比率单位**：一律 **0–1 小数（4 位小数）**，与 scheduling.yaml 的
   `utilizationRate/onTimeRate/cancellationRate` 一致；前端乘以 100 展示为百分比。
   分母为 0 返回 0，不返回 404/NaN。
9. **术间状态映射**：`ANESTHESIA`/`SURGERY`→`IN_SURGERY`、`IDLE`→`IDLE`、
   `CLEANING`→`CLEANING`、`PREPARING`→`PREPARING`、`PACU`→`RECOVERY`；
   **软删除术间按“停用”（`OUT_OF_SERVICE`）计入**——M1 无独立停用状态，停用语义暂由软删除
   承载【待确认】；未知状态同样按停用处理（绝不把状态不明的术间计入空闲/手术中）。
10. **告警计数**：只统计当日触发、`status=TRIGGERED` 的未确认告警，并按 `severity` 分列
    （`critical+warn+info = unacknowledgedCount`）；已确认/已忽略单列。**不返回**告警值、
    规则原文、处置原因与患者/记录单标识——钻取走 M2 告警详情接口并受其权限约束。
11. **设备在线**：查询期推导 `status ≠ MAINTENANCE AND last_seen_at > now − 120s`
    （`device-offline-timeout-seconds`），与 M2 采集离线判定一致，不写回
    `device_registry.status`；`offline = total − online − maintenance`。
12. **数据时效**：`dataDelaySeconds = now − max(台次 updated_at, 记录单 updated_at,
    告警 triggered_at, 设备 last_seen_at)`；`dataQuality`：`NO_DATA`（无任何数据）/
    `OK`（≤ 阈值）/ `DEGRADED`（> 阈值）。阈值默认 120s，**配置超过 120s 拒绝启动**
    （方案书“延迟超过 2 分钟须标注”是硬约束，不允许被配置放宽）。
13. **数据范围 fail-closed**（与 M4 报表同构）：`ALL` 全院；`SITE`/`DEPT` 按术间院区/科室
    （台次另按申请科室/院区）；`ROOM` 按术间；`SELF` 按**本人创建麻醉记录单的当日台次所涉
    术间**过滤（聚合无 PHI，幂等：重复应用同一范围不改变结果）。无可用范围、SELF 缺用户
    标识 → 403，绝不退化为全院查询；投影层再做一次纵深防御。
14. **只读跨模块投影放在装配层**：m5-api 定义 `DashboardCaseSource`/`DashboardRoomSource`/
    `DashboardAlertSource`/`DashboardDeviceSource` 四个只读端口，由 api-bootstrap 的
    `Dashboard*SourceAdapter` 用**单条只读 SELECT** 投影（不依赖 m1/m2 的 Mapper/实体，
    不写任何模块的表，不做时区换算）。m5-impl 只做校验、数据范围解析、聚合与审计
    （可在单测中用手算数据覆盖）。
15. **审计 `DASHBOARD_VIEW`（采样）**：按“用户 + 看板类型”在采样窗口（默认 300s）内只写一条，
    detail 仅看板类型/日期/数据范围/术间数/台次数/告警数/延迟，不含患者标识与处置原因。
    看板读审计不是合规强留痕，写操作审计不受影响。
16. **权限**：V26 data-only 新增 `m5:dashboard:read`，最小授予 SYS_ADMIN / SYS_OR_MANAGER /
    SYS_ANESTHESIOLOGIST / SYS_QC_MANAGER；不授予手术医师/麻醉护士/药师/手术室护士
    （驾驶舱为管理视角聚合数据，是否放开给术间护士待院方确认）。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| SSE/WebSocket 推送 | 需长连接与广播治理、前端重连状态机与多实例一致性；看板 10s 粒度足够，轮询更简单可回滚 |
| 新建 `m5_dashboard` 结果表/物化视图 | V26 要求 data-only；结果表与源数据易漂移，且看板语义是“当前快照” |
| 后端缓存实时快照 | 多实例一致性与失效逻辑复杂；直接查源表在单院数据量级下已是毫秒级 |
| 准点率直接用台次 `updated_at` | 记录单 `started_at` 更接近真实开台；保留回退路径以兼容缺记录单的术间 |
| 逐次写审计 | 10s 轮询会在审计表产生每小时 360 条/用户的噪声，掩盖真正的安全事件 |
| 停用术间不计入 | 大屏需要看到“停用”资源，否则术间总数与排程能力对不上；以软删除近似【待确认】 |
| 比率返回百分比 | 与既有 scheduling.yaml 的 0–1 小数不一致，前端需两套换算 |

## 后果（正面/负面/代价）

- 正面：口径与 M2-M6-01、M4-M16-01 同源可追溯；无 PHI、权限最小、审计采样不刷屏；
  看板为纯只读聚合，不新增表、可随时下线回滚；10s 轮询无新依赖。
- 负面：准点率/利用率的真实可用性仍受“实际开台时间”写入路径缺失限制（多数术间可能只有
  `updated_at` 近似）；停用术间语义、SELF 范围是否满足个人看板仍待院方确认。
- 代价：每次口径调整需评审并同步契约/README/数据字典；轮询失败时前端保留旧快照（需展示
  延迟标识避免“看似实时”）。
- 解除条件：院方确认 Q-1–Q-4；M3/HIS 回写实际开台/结束时间；如需秒级实时再评估 SSE。

## 待确认（Q）

- **Q-1 实际开始时间来源**：记录单 `started_at` 优先、缺失回退台次 `updated_at` 是否可接受。
- **Q-2 利用率口径**：计划手术时长 vs 实际占用时长；停诊日/未来日是否计入分母（ADR-0015 Q-3）。
- **Q-3 停用术间**：M1 无独立停用状态，暂以软删除表示；是否需要独立停用/维修状态。
- **Q-4 权限与 SELF 范围**：SYS_ANESTHESIOLOGIST（SELF）按“本人台次所涉术间”看态势是否
  满足需求；是否向术间护士/手术医师开放只读看板。

## 追加决策（2026-11-15，M5-M18-02 风险与资源大屏，契约 0.2.0 / 口径 dashboard-1.1.0）

M5-M18-02 在 0.1.0 的实时态势/KPI 之上新增三个**只读聚合**端点，决策如下（additive，不改
0.1.0 任何字段与语义）：

17. **风险分层（`GET /v1/dashboard/risk`）**：以 M1 当日非取消台次为骨架，取**每份申请最新
    一份已最终化**（`status=FINALIZED` 且未删除）的 M2 术前评估，按 `(asa_class, risk_level)`
    分组计数；未评估台次（未访视/仅草稿）单列 `unassessedCaseCount`，不进入分布。
    高危 = `ASA ≥ III` **或** `risk_level = HIGH`（每个台次只有一个组合，按组合去重）；
    严重告警取当日未确认 `CRITICAL` 数（同 0.1.0 告警口径）；**不返回**评分明细、患者/台次标识。
18. **超时台次（【待确认】Q-5）**：`delayedStartCount` = 计划开始 + 宽限 < now 且未开始；
    `overrunCaseCount` = 计划结束 + 宽限 < now 且未完成；`overdueCaseCount` 为两者**并集**
    （同一台次只计 1，避免大屏重复计数）；宽限 `anesop.m5.dashboard.overdue-grace-minutes`
    默认 0、允许 0–120，启动校验；“未开始/未完成”沿用 ADR 第 4 条的记录单/状态判定；
    取消台次不参与。
19. **资源态势（`GET /v1/dashboard/resources`）**：术间利用率复用 KPI 的同源公式（同一属性
    `roomUtilization`，不另立口径）；术间状态分布复用 0.1.0 映射；设备在线率 =
    在线 / 总数（查询期推导，不写回）；当班人员取 M4 `staff_schedule` 当日 `PLANNED`，
    按 `staff_id` 去重给出 `total`、按班次分组给出 `byShift`（同一人跨班次会在两个班组各计 1，
    因此**不得用班组之和替代 total**）【待确认】Q-6。
20. **资源缺口提示（`resourceGaps`）**：确定性规则，顺序固定（设备离线 WARN、设备维护 INFO、
    停用术间 INFO、排程超载 WARN、当班人员为 0 WARN、无可见术间 WARN），每项只含
    编码/级别/计数/中文提示，**不含任何人员、设备与患者标识**。缺口是展示辅助，不构成
    临床或管理决策（AGENTS H-06），阈值与是否分科室细化【待确认】Q-6。
21. **趋势（`GET /v1/dashboard/trends`）**：窗口 `hours ∈ [0.5, 24]`（30–1440 分钟），
    终点固定为服务端当前时刻；桶按 `Asia/Shanghai` 整点对齐（上海无夏令时，UTC 整点与本地
    整点一一对应，适配器 `date_trunc('hour')` 无需时区换算）；首末桶按窗口交集裁剪。
    桶内：告警 = 触发数（不限处置状态）、台次 = 计划开始落在桶内的非取消台次、
    `utilizationRate` = 桶内重叠手术分钟 /（可见术间数 × 桶与窗口交集分钟）。
    **不返回** `dataDelaySeconds`/`dataQuality`：小时桶是聚合值，单值延迟无意义，
    实时时效标注仍以 `/v1/dashboard/realtime` 为准；该取舍写入契约 description，避免前端
    误把趋势桶当作“当前时刻快照”。
22. **权限与审计不变**：三端点复用 `m5:dashboard:read`（V26 已按 `/api/v1/dashboard/*` 路径
    授权，无需新迁移）；审计仍为 `DASHBOARD_VIEW`（采样），`resource_id` 为
    `risk`/`resources`/`trends`，detail 只加计数（`assessedCaseCount`/`highRiskCaseCount`/
    `overdueCaseCount`/`staffOnDutyTotal`/`deviceOffline`/`windowMinutes`/`pointCount`），
    不含患者标识、人员标识与自由文本。
23. **SELF 范围的边界**：风险/趋势沿用“本人台次所涉术间”；**人员排班无用户标识**，
    无法按“本人”精确裁剪，资源端点对 SELF 取“本人当日台次所涉**科室**的当班人数”，
    属最小可见近似（【待确认】Q-6），始终 fail-closed（不会放大到全院）。
