# ADR-0025：消息业务投递与体征映射口径（M9-01）

- 状态：已接受（实现随 M9-01 落地；频率/免打扰/升级路径与临床口径仍为【待确认】）
- 日期：2026-11-15
- 关联：M8-M4-01（消息中心“有入站、无投递”）、FINAL-REPORT §6.2 三项遗留、
  ADR-0016（设备采集与体征质量）、ADR-0018/0019（药品字典与麻精五专）、ADR-0024（字典消息文件）
- 决策类型：可逆（表结构只加一列；消息投递可关闭调度回退；体征映射为只读投影）

## 1. 背景

M8 收口后仍有三项 P1 遗留：

1. **消息只有入站与已读**：`m1_sched.notification_outbox` 的 `NotificationPort.deliver`
   只写日志（SIMULATED），调度停改台/急诊审批、m2 CRITICAL 告警都没有真正进入 m0 消息中心；
2. **记录单 `vitalSigns` 恒为空数组**：采集域已有 `m2_anes.anesthesia_vital` 与设备台账，
   但记录单没有按“记录时间窗 + 术间”映射，前端只能显示“待采集接入”；
3. **抢救用药未强制麻精判定**：记录单用药已按 m4 药品字典判定并强制第二核对人，
   抢救记录的 `drugs` 仍只校验名称/剂量，麻精属性与核对人可被绕过。

三项都涉及“临床/管理口径未签字”的边界。本 ADR 只固化**可逆、最小、不臆造口径**的实现，
把频率、免打扰、升级路径与体征聚合口径登记为【待确认】。

## 2. 决策

### 2.1 消息业务投递：outbox → 默认通知矩阵 → 站内消息

- `NotificationPort` 保持两段式：`publish` 写 outbox（与业务事务同提交），
  `deliver` 由 `NotificationDispatcher` 轮询调用。
- `deliver` 按**默认通知矩阵**把事件翻译成 m0 站内消息（`MessagePublisher`）：
  接收人 = 角色下的**启用用户**（`status=1`、未删除），由 m0-api
  `NotificationRecipientDirectory` 解析，m1 不访问 m0 用户/角色表。
- 模板（`MessageTemplates` 注册表，服务端固定标题 + 参数白名单）：

| 业务事件 | 模板编码 | 消息类型 | 接收角色 |
|---|---|---|---|
| `SCHEDULE_MODIFIED` / `SCHEDULE_PREEMPTED` | `SCHEDULE_CHANGE` | `SCHEDULE` | SYS_ANESTHESIOLOGIST + SYS_OR_MANAGER |
| `SCHEDULE_STOPPED` | `SCHEDULE_STOP` | `SCHEDULE` | 同上 |
| `EMERGENCY_SCHEDULED` | `EMERGENCY` | `SCHEDULE` | 同上 |
| `ALERT_CRITICAL`（含未确认） | `CRITICAL_ALERT` | `ALERT` | 同上 |

- **SYS_ADMIN 不默认投递【待确认】**：避免管理员被临床告警淹没；如院方要求纳入，
  只需在路由角色表中追加，不改表结构与契约。
- **频率/免打扰/升级路径【待确认】**：本期为“事件即投递一条”，不做聚合、限频、夜间免打扰、
  未读升级（如 30 分钟未读转短信）。真实短信/企业微信仍属 EXT，不在本期。
- **去重**：`sys_message.dedupe_key`（V29 唯一索引）= `OUTBOX:<outboxId>:<recipient>:<template>`，
  同一业务事件 + 接收人 + 模板只落一条；重试/并发派发命中唯一键时返回既有消息。
- **无 PHI**：参数只从模板白名单键取值（台次/术间/时间/原因码/告警标识/指标/严重度），
  payload 中其他字段一律丢弃；日志只记事件类型、outbox 标识、接收人数。

### 2.2 记录单体征映射：m2 内部只读端口

- 记录单 `GET /v1/anesthesia/records/{recordId}` 的 `vitalSigns` 由 m2 内部只读端口
  `VitalSignReadPort` 查询：`anesthesia_record.room_id`（创建时快照）关联
  `device_registry.room_id`，窗口 `[started_at, ended_at 或 now]`，读 `anesthesia_vital`。
- 输出按 `measuredAt` 升序，每帧按指标展开为
  `metric/value/unit/measuredAt/quality/qualityFlags`；最多 2000 条，超出返回
  `vitalSignsTruncated=true`（不静默截断）。未开始（无 `startedAt`）或术间为空返回空数组，
  **不伪造数值**。
- 只读、无 PHI，不修改采集链路；不跨模块 Mapper（设备/体征均在 m2 自身 schema）。
- **体征聚合口径【待确认】**：本期返回**原始采样点**（可能 1 Hz，条数大），不做 1/5 分钟
  抽稀或趋势聚合；如临床要求“记录单只显示 5 分钟趋势”，另立任务加服务端聚合与采样参数，
  不改本 ADR 的字段语义。
- 兼容：0.11.0 为 additive，保留 `heartRate/systolicBp/...` 整帧字段，映射时对应指标同时填充。

### 2.3 抢救用药麻精判定：与记录单同一口径

- `ResuscitationDrug` 每项经 m4-api `DrugDictionaryService.findByName` 解析：
  未收录 400；名称/通用名/别名命中多个 422 `DRUG_AMBIGUOUS`（fail-closed）。
- `narcotic` 由字典判定；客户端声明与字典不一致 400（以字典为准，防误报 false 绕过核对）。
- 字典麻精必须 `secondCheckerId/secondCheckerName`：缺失、同人、不存在、停用、
  无 `m2:record:write` 均 400；复用 `SecondCheckerEligibility`（与记录单相同规则）。
- 第二核对人随 `drugs` jsonb 落入既有 `m2_anes.resuscitation_record`，**不新增列**；
  append-only 与时间窗约束不变。审计 `RESCUE_RECORD` 增加 `narcoticCount/secondCheckCount`，
  仍不含人员姓名与事件摘要原文。
- **麻精判定时点【待确认】**：按“抢救记录提交时”的字典版本判定，历史记录不回溯重判；
  字典停用药品仍可解析历史属性（`active=false`），是否允许新录入由调用方决定（本期未额外拦截）。

## 3. 备选方案与取舍

| 方案 | 结论 | 理由 |
|---|---|---|
| m1 直接写 m0 `sys_message` 表 | 否决 | 跨模块访问数据表，违反 AGENTS 模块边界 |
| 在 api-bootstrap 放通知适配器 | 否决 | 端口实现分散、测试需启动整栈；m1-impl 依赖 m0-api 已足够 |
| 每个事件即时发短信/企业微信 | 否决（EXT） | 院方通道未接入；频率/免打扰口径未定 |
| 消息去重放应用层“先查后插” | 否决 | 并发下仍会重复；数据库唯一键是唯一可靠兜底 |
| 记录单 `vitalSigns` 返回聚合趋势 | 否决（本期） | 聚合口径（窗口/抽稀/中位数）属临床口径，未确认前不固化 |
| 抢救第二核对人单独建表/列 | 否决 | drugs 为 append-only jsonb，逐项建列会破坏不可变明细结构 |
| 抢救用药允许自由文本 | 否决 | 无法判定麻精，等于绕过双人核对 |

## 4. 影响

- 契约：`anesthesia.yaml` 0.11.0（additive）、`platform.yaml` 0.2.1（仅描述）。
- 数据库：V29 只加 `m0_platform.sys_message.dedupe_key` 与唯一索引；无新增权限点。
- 运行时：m1 通知派发改为写消息中心（可用 `anesop.m1.notification.scheduler-enabled=false` 关闭）；
  m2 记录详情多一次只读查询（窗口 + 术间，最多 2001 帧）；CRITICAL 告警会在同一事务内写 outbox。
- 性能：体征窗口在 1 Hz × 数小时场景可能触达 2000 条上限，已显式标记截断；后续如需分页，
  另开 `GET /records/{id}/vitals` 端点（additive），不改本字段。
- 安全：消息无 PHI；体征无患者标识；抢救审计不含姓名/摘要原文。

|---|---|---|---|
| Q-M9-01 | 通知矩阵频率、免打扰、未读升级路径 | 消息量/夜间打扰/漏读风险 | 院方管理口径确认后改配置或加调度 |

| Q-M9-04 | 抢救麻精判定是否回溯历史记录 | 历史数据解释 | 医务/药学确认；本期不回溯 |
| Q-M9-05 | 停用药品是否允许新抢救录入 | 用药安全/历史一致性 | 药房/医务确认；本期可解析历史属性但不额外拦截 |
