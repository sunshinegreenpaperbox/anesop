# ADR-0017 术中预警触发入口、间歇指标窗口与抢救留痕

- 状态：已接受（临床口径待确认）
- 日期：2026-11-14
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策；临床口径标注待确认）
- 关联：M3-M2-02 / 方案书 §2.4.3 / AGENTS 临床规则高风险

## 背景与约束

M3-M2-02 首版把预警评估放在"查询时 + 手动 evaluate"，评审判定不可合入：纯监护页面
长时间无交互不产生告警；长台次体征样本保留窗口（1 Hz × 20000 ≈ 5.5h）会丢失早期数据；
读旧记录用当前规则重评会产生追溯性假告警；间歇指标（NIBP/EtCO2/体温）空帧会重置
duration 窗口；DRAFT 记录会误用同术间上一台次患者体征；抢救记录缺人员/负责人字段。

## 决策

1. **触发入口改为"采集落库后领域事件 + 前端轮询兜底"**：
   - m2 采集服务 ingest 成功提交后（`@TransactionalEventListener(AFTER_COMMIT)` 领域事件）
     触发评估，仅评估 `status=ONGOING 且 startedAt != null` 的记录；
   - 记录单创建时通过 m1-api（只读接口）快照 `roomId`/`scheduleId` 到 m2 自己的表，
     采集侧不跨模块读 m1 表；按 roomId + 时间窗匹配活动记录；
   - 长台次按"时间水位"增量推进（已评估到的 measured_at 水位），不重复扫描；
   - 前端记录页 5–10s 轮询告警 + 手动评估按钮（补偿/测试），轮询不依赖 `alert:read` 以外的权限。
2. **间歇指标窗口**：duration 判定只使用**该指标非空样本**的测量时间；每类指标独立
   gap 容忍（配置化，默认：连续波形类 10s、NIBP/EtCO2/体温 300s）；空帧不重置窗口、
   重复值不累加时长；等于阈值不触发。临床确认前阈值与 gap 标【待确认】。
3. **DRAFT 不评估**：`startedAt == null` 或非 ONGOING 时返回空告警；评估窗口一律从
   `startedAt` 起，禁止用 `createdAt` 兜底；补"草稿 + 同术间上一台次体征"负向用例。
4. **抢救留痕**：抢救记录增加结构化 `leader`（负责人）与 `rescuers`（参与者列表，
   至少 1 人）字段，保留原有事件/用药/结局；append-only 不变。
5. **规则治理**：规则名称可更新但阈值变更需临床确认标记（`pendingConfirmation` 字段）；
   阈值按指标范围校验（SpO2 0–100、HR 0–300、MAP 0–250、EtCO2 0–150、TEMP 25–45）；
   提供规则版本历史查询，告警记录 `ruleVersion` 可追溯当时阈值。
6. **审计修正**：ALERT_TRIGGERED 的 `resourceId` 使用 alert 主键、`resourceType=ALERT`；
   手工评估记录调用人；审计 detail 不含患者标识/原因原文（抢救原因仅留 id）。
7. **待确认（必须回写）**：
   - Q-1：quality=1（可疑）帧是否可触发 CRITICAL，还是仅提示/人工确认；
   - Q-2：同一越界窗口 ACK 后是否按 N 分钟升级再提醒（以及声音/大屏通知）；
   - Q-3：默认阈值（SpO2<90、HR<50/>120、MAP<65、EtCO2 范围、TEMP）与间歇指标 gap；
   - Q-4：抢救负责人/参与者是否必须绑定当前登录用户与 CA 签名（M5/M3-M2-03）。
8. **发布准入**：预警规则与阈值属临床规则，生产启用前须临床顾问逐项确认第 7 条并签字；
   E2E 告警流（触发→确认→抢救）纳入 M3-QA-01。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 保持查询时评估 | 临床安全不可接受：无人看页面即无告警 |
| 采集侧直接查 m1 表 | 违反模块边界；改为 m1-api 只读接口 + 记录快照 roomId |
| 统一 300s gap 对所有指标 | 1 Hz 波形与 NIBP 采样率差异过大，必然误判/漏判 |
| 用 createdAt 兜底窗口 | 会把上一台次患者体征算入本记录（错误患者告警） |
| 抢救只记录入人 | 临床留痕不完整，无法追溯负责人/团队 |

## 后果（正面/负面/代价）

- 正面：告警实时、按患者记录隔离、间歇指标语义正确、规则可追溯、抢救留痕完整；
  审计可关联 alert 主键。
- 负面：ingest 事件评估增加写入路径复杂度与性能开销（批量/异步处理）；roomId 快照需
  V16 迁移与回填；阈值/gap 仍需临床确认；规则变更临床复核流程未自动化。
- 代价：V16 迁移 + 事件监听 + 测试矩阵扩大；每次规则调整需重评估历史水位（仅新数据）。
- 解除条件：临床确认 Q-1…Q-4；M3-QA-01 E2E 告警流；M5 药品/设备字典完善后自动判定质量。
