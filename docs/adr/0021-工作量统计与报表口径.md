# ADR-0021 工作量统计与报表口径

  §3.8.1（月度工作量报表 < 10s）/ E-M16 / D-21（系统出数、绩效规则院方另定）/

## 背景与约束

M4-M16-01 交付工作量统计、多维报表与 CSV 导出。方案书要求“例数、台次、麻醉时长、
难度系数”“多维度统计、绩效口径配置、报表导出”，但**未冻结分子/分母、维度归属、权重
来源与报表锁定规则**；D-21 明确“系统出数、绩效规则院方另定”。同时存在三条硬约束：

1. 统计单元分散在 M1 排程台次（`m1_sched.schedule`/`surgery_application`）、M2 麻醉记录单
   （`m2_anes.anesthesia_record`）与 M4 人员档案（`m4_staff.staff_profile`）；
2. AGENTS 禁止跨模块访问对方数据表/Mapper，也不允许 m4 反向依赖 m1-api/m2-api 形成模块环；
3. V24 限定为 **data-only** 迁移（只加权限点，无 DDL），因此不可能新建报表结果表或物化视图。

导出侧风险与排程分析同源：CSV 若不做公式注入防护，主数据字符串列（术式名、科室名）可能
被 Excel/Sheets 当作公式执行；患者标识一旦进入导出即触犯数据红线。

## 决策

1. **时间口径**：所有统计按 `Asia/Shanghai` 自然日；`from`/`to` 必填且为闭区间，跨度
   （含首尾）**≤ 366 天**，超过返回 400。上限写死在契约与实现（不开放配置，避免契约漂移）。
2. **台次口径（统计边界）**：统计单元为 M1 台次，`deleted=false` 且 `status ≠ CANCELLED`；
   按**计划开始时间 `start_at` 的本地日期**归集，跨日台次只计首日、不按跨越拆分
   （与排程分析 analytics-1.0.0 的归属一致）。取消台次不计入台次与时长。
3. **麻醉时长**：取麻醉记录单 `started_at`..`ended_at` 之差**向下取整到分钟**并求和（实际
  记录时间，非计划时长）；无记录单、未结束或时间缺失计 0，并单列 `unrecordedCaseCount`
   （有台次无可用时长），让“缺记录”可见而不是被静默平均。跨零点按绝对时间差计算。
4. **权重（加权台次）**：`weightedCaseCount = Σ 台次权重`；默认 **1.0**，可按术式编码配置
   `anesop.m4.report.surgery-weights.<code>`，未配置取默认值；权重必须 > 0（启动校验）。
   **系统不内置任何绩效公式、难度系数或金额**——难度系数与二次分配由院方按 D-21 另行制定，
   本契约只提供可配置系数与系统出数（【待确认】Q-1）。
5. **维度白名单**：
   - `DEPT` = 申请科室（`surgery_application.dept_id/dept_name`，与申请归属一致）；
   - `STAFF` = 麻醉医师（麻醉记录单 `created_by` → `m4_staff.staff_profile`）；
   - `SURGERY` = 术式编码（`surgery_code`）；`ROOM` = 术间（`room_no`）。
   未匹配进入固定兜底桶（`UNASSIGNED`/`UNSPECIFIED`），排序固定最后，**保证各维度台次之和
   与总计守恒**。`STAFF` 以记录单创建人近似“执行医师”、`DEPT` 以申请科室近似“手术科室”，
   两者口径【待确认】（Q-3）。
6. **指标白名单与分页**：指标 `caseCount`/`anesthesiaMinutes`/`weightedCaseCount`；维度白名单
   全集 4 个（去重后 1–4 个）、指标全集 3 个（去重后 1–3 个），任一非白名单值/空值返回 400
   （不回显原始输入）；数量上限由白名单全集天然约束，不设不可达的越界分支。
   分组按维度声明顺序 + 维度值升序**稳定排序**，兜底桶固定最后，`page` 从 1 开始、`size` 1–200；
   `total`/`totals` 覆盖**全部分组**（不受分页影响），空数据 `total=0/totalPages=0`。
7. **数据范围 fail-closed**：`ALL` 全院；`SITE`/`DEPT` 按台次申请科室（或院区）；
   `ROOM` 按术间；`SELF` 只含**本人创建麻醉记录单**的台次。无可用范围、SELF 缺用户标识、
   `deptId` 超出组织范围一律 403；`deptId` 只是收窄条件，绝不扩大可见范围。
   科室下拉由 DEPT 维度桶派生，不依赖 `m1:schedule:read`（与排程分析 S-1 一致）。
8. **只读跨模块投影放在装配层**：契约与实现不新建表，统计单元通过 m4-api 端口
   `ReportCaseSource` 获取，由 `api-bootstrap` 的 `ReportCaseSourceAdapter` 用**单条只读
   SELECT** 投影（不依赖 m1/m2 的 Mapper/实体，不写任何模块的表，不做时区换算）。
   投影层再做一次纵深防御：非全院且 `orgIds`/`roomIds`/SELF 全空时直接 403，绝不退化为
   全表查询。m4-impl 只做校验、数据范围解析、聚合与导出（可在单测中用手算数据覆盖）。
9. **导出脱敏与防注入**：CSV 为 UTF-8 **BOM**、首行列头、`text/csv` 流式输出；单元格命中
   公式起始字符（`=`/`+`/`-`/`@`/制表符/回车）时以**前导单引号中和**，必要时按 **RFC 4180**
   加双引号并转义内部引号。
   导出只含科室/术间/术式/院内在册人员工号与姓名与聚合值，**不含**患者姓名、住院号、
   院内患者号、身份证号、手机号、术前诊断、HIS 申请号；导出写审计 `REPORT_EXPORT`
   （查询写 `REPORT_QUERY`），detail 仅 report/日期/维度/指标/行数。
   参数校验与数据范围解析在任何字节写出前完成，非法参数仍返回 JSON 400/403。
10. **权限与审计**：V24 data-only 新增 `m4:report:read|export`，最小授予 SYS_ADMIN /
    SYS_OR_MANAGER / SYS_QC_MANAGER；read 的权限 path 用 `/api/v1/reports/*` 覆盖 workload
    与 multi，不新增权限码；两条 INSERT 带 `ON CONFLICT DO NOTHING` 便于重复演练。
    临床个人工作量视图待绩效方案确认后另开（Q-1/Q-5/Q-7）。
11. **性能**：单次查询为“按时间区间 + 可见范围”的台次投影（数千行）在应用内聚合。
    本机基线（2026-11-15，JDK 21）：5000 台次 / 366 天区间的工作量聚合
    **约 60ms（实测 59–63ms）**（单测 benchmark，断言 < 5000ms），接口端到端为单条索引
    扫描 SQL + 同一聚合路径，距方案书 §3.8.1“月度工作量报表 < 10s”留有一个数量级余量；
    导出分组数上限 50000（超过 400，避免一次导出拖垮应用），workload 导出上限见 Q-8。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| V24 新建 `m4_report` 结果表/物化视图 | 任务要求 data-only 且报表结果与源数据易漂移；锁定/定时生成属 §2.4.7 后续需求，另开迁移 |
| m4-impl 直接写跨 schema SQL Mapper | 违反模块边界（访问其他模块数据表），且把跨模块读取散落到业务层 |
| 让 m1/m2 暴露台次列表 API 供汇总 | 会改动 m1/m2 业务代码（超出写域），且列表 API 的字段与报表口径耦合 |
| STAFF 用 `staff_schedule` 排班归属 | 排班≠实际执行人，且无排班记录时全部落空；记录单创建人是更强的“谁做了这台”信号 |
| 权重内置“难度系数表” | 无院方口径，属臆造绩效规则（AGENTS H-04/H-06、D-21） |
| 缺失记录单的台次直接不计台次 | 会掩盖漏记；计台次 + `unrecordedCaseCount` 单列更透明 |
| 按维度值大小写/中文排序 | 受数据库 collation 影响不可复现；改为应用内按编码稳定排序、兜底桶固定最后 |

## 后果（正面/负面/代价）

- 正面：口径可解释（台次/时长/权重/维度归属写进契约 description）、手算可验证、导出可复核；
  data-only 迁移不引入表变更；跨模块只读收口到一个装配层适配器；审计与脱敏可测。
- 负面：报表不落库，无法“锁定月度报表”（方案书 §2.4.7 的数据锁定与修订留痕留待后续）；
  统计结果随源数据变化，历史报表重跑可能得到不同数字（口径未变时由源数据修订导致）；
  STAFF/DEPT 归属为近似口径，待院方确认。
- 代价：每次口径调整需评审并同步契约/README/ADR；CSV 防护需覆盖所有导出列；
  跨模块投影 SQL 需随 M1/M2 字段变更同步维护（由集成测试的手算断言兜底）。
- 解除条件：院方确认 Q-1…Q-8；如需报表锁定/定时生成，新增 V25+ 读模型与锁定表并升契约。
