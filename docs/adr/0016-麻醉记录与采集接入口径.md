# ADR-0016 麻醉记录单与采集接入平台端口径

- 状态：已接受（临床/安全细节待确认）
- 日期：2026-11-14
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策；临床/安全口径标注待确认）
- 关联：M3-M2-01 / M3-M8-01 / 方案书 §2.4.3 / §3.6 / EXT-04

## 背景与约束

M3 第一批实现麻醉记录单/时间轴（事件、用药、输液、出入量）与设备采集平台端接入
（设备登记、网关 ingest、质量标记、幂等、健康查询）。临床记录属于发布准入最高风险域；
方案书要求"锁定后不可变、只能修订"、"补录须标注录入时间与原因"、"麻精双人核对"、
"断网缓存 ≥4h 与幂等补传"。M3-M2-03（锁单/修订）尚未实现；真实设备协议与网关凭证
（EXT-04）不可用。

## 决策

1. **记录不可变**：`record_event`/`drug_administration`/`fluid_record` 由 DB 触发器实现
   append-only（UPDATE/DELETE/TRUNCATE 均 55000）；记录单壳在 M3-M2-03 锁单前可改，
   身份列（台次/申请/患者）不可变；锁单后只能新建修订版本（M3-M2-03 实现）。
2. **并发与序号**：事件 `seq` 在 `SELECT ... FOR UPDATE` 锁定记录单行后分配并插入，
   不做"唯一键冲突后重试"（PG 事务已 aborted）；并发追加测试必须用真实 PG 双线程。
3. **补录与时间校验**：`occurredAt` 早于最新事件或早于 `now - 容差` 时必须提供
   `entryReason`（缺失 400）；禁止未来时间（now+容差）与 ANESTHESIA_END 之后追加；
   事件顺序约束（INTUBATION 不早于 ANESTHESIA_START）。"记录开始"口径（急诊回溯）待
   临床确认（Q）。
4. **麻精双人核对（MVP）**：`narcotic=true` 必须提供第二核对人；服务端校验核对人存在、
   在职、非本人、具备 `m2:record:write`。**T-4 已由 M4-M15-01 收口（2026-11-14）**：
   `narcotic` 由服务端按 m4-api 药品字典判定（名称/通用名/别名 trim + 忽略大小写），
   字典未收录 400、解析命中多个药品 422 `DRUG_AMBIGUOUS`（fail-closed）、客户端声明与
   字典不一致 400（以字典为准）；客户端不得再自行决定麻精标志。
5. **采集平台端**：设备登记 `m2_anes.device_registry`（唯一 gatewayId+deviceId），
   网关经 `X-Gateway-Token` 调用 ingest（fail-closed、等长常量时间比较、token 不落日志）；
   幂等由 `device_ingest_log`（gatewayId+batchKey 唯一）与 `anesthesia_vital` 行唯一键
   双层保证；质量标记/拒绝原因计数入库；`last_seen_at` 仅在 accepted>0 时推进。
6. **数据范围**：设备台账/体征查询/登记换台按 m0 DataScope + m1 可见术间过滤
   （denied 403、越界 404）；未绑定术间仅 ALL 范围可见。
7. **采集安全（待确认）**：当前为共享网关 token，未与 gatewayId 绑定（持 token 者可向
   任意已登记设备注入）；生产前需单网关密钥或 token→gateway 映射（已登记 Q）。
8. **契约与生成**：anesthesia 0.5.0 与 device.yaml 0.1.0 additive；device 域纳入
   spectral/oasdiff/HEAD baseline/TS 与 Java 代码生成（api-contracts 第 5 个 execution）；
   移除不可达的旧描述字段属 1.0.0 major 清理（ADR-0011）。
9. **待确认（必须回写）**：
   - Q-1：记录开始口径与急诊回溯（created_at floor 是否允许回溯到台次计划开始 + entryReason）；
   - Q-2：麻精核对留痕强度（仅 id+姓名+时间 vs 生物认证/CA，M5/M3-M2-03 前）；
   - Q-3：临床角色如何获取本台体征（记录单 `vitalSigns` 映射口径，M3-QA/M4 权限细化）；
   - Q-4：共享网关 token 的生产收敛方案（单网关密钥/映射）。
10. **发布准入**：时间轴、断网采集补传、并发修改、签名锁定为发布准入项；E2E-02（断网补传）
    与 E2E-03（锁单修订）由 M3-QA-01 承接。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 唯一键冲突后重试 seq | PG 事务 aborted 后无法继续（25P02）；行锁分配更简单可靠 |
| 药名/麻精标志由客户端决定 | T-4 风险；已由 M4-M15-01 药品字典服务端判定收口 |
| 采集直接由网关直连 PG（现状） | 无平台侧校验/审计；新增 ingest + 平台查询（网关仍可配置 jdbc 模式） |
| 共享 token 长期使用 | 无法隔离多网关；生产前必须收敛（Q-4） |
| 设备台账不做数据范围 | 与 DEPT/ROOM 最小权限冲突；已改为可见术间过滤 |

## 后果（正面/负面/代价）

- 正面：临床事件不可篡改、并发写入安全、补录可追溯、麻精核对有留痕；采集双层幂等、
  质量可观测、设备台账受数据范围约束；契约/生成链路完整。
- 负面：锁单/修订未实现（M3-M2-03）；共享 token 未绑定网关；记录单 `vitalSigns` 仅为
  占位（映射口径待 Q-3）；新增 device Java 生成使 SpotBugs 内存需求上升（maxHeap 已调至
  2048）。麻精标志的客户端绕过风险已随 T-4 收口关闭（剩余为字典命名纪律，见 ADR-0018）。
- 代价：V13/V14 触发器与约束增加写路径复杂度；每次契约变更需重生成 5 域 Java/TS。
- 解除条件：M3-M2-03 锁单/CA；EXT-04 网关凭证；临床 Q-1/Q-2/Q-3 确认。M5 药品字典
  已提前由 M4-M15-01 落地并收口 T-4。
