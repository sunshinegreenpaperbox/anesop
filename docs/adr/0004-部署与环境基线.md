# ADR-0004 部署与环境基线（Compose）

- 状态：已接受
- 日期：2026-11-12
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策）
- 关联：S0-10 / 方案书 §3.7「部署架构」/ EXT-08（Docker 不可用）

## 背景与约束

S0-10 要交付单院私有化的 Docker Compose 一键起环境。当前宿主机 **Docker 不可用**
（无 daemon；EXT-08），因此无法实测 `docker compose up`、无法拉取镜像、无法生成
镜像 digest、无法跑容器化集成测试。方案要求服务清单为 PostgreSQL 16、Redis 7.2、
RabbitMQ 3.13、MinIO、Nginx、API、Web，并带健康检查与依赖顺序；详细拓扑与生产加固
未逐行规定，按 AUTONOMY §2 选定并记录。

## 决策

1. **Compose 作为单院生产基线**（`deploy/compose/docker-compose.yml`）：9 服务 =
   postgres / redis / rabbitmq / minio / api / web + 监控三件套（prometheus / grafana /
   loki，`profiles: [monitoring]`，默认不启动）。网络分 `anesop-net` 与
   `anesop-monitoring`；数据卷 7 个（pgdata/redisdata/rabbitmqdata/miniodata/promdata/
   grafanadata/lokidata）。
2. **最小暴露面**：仅 `web` 映射宿主 80/443；postgres/redis/rabbitmq/minio/api 只用
   `expose` 不映射；监控端口绑 `127.0.0.1`（9090/3000/3100）。
3. **依赖与健康**：所有服务 `restart: unless-stopped` + `healthcheck`；`depends_on`
   用 `condition: service_healthy`；api 健康检查走 `/actuator/health`，web 走
   `/healthz`；资源限制、json-file 日志轮转、`security_opt: no-new-privileges` 全服务开启；
   api 容器以非 root（UID 10001）运行。
4. **镜像与构建**：镜像使用精确版本 tag（postgres:16.4、redis:7.2.5、
   rabbitmq:3.13.7-management、minio RELEASE.2024-08-17T01-24-54Z、prometheus v2.55.1、
   grafana 11.2.2、loki 3.1.1），**禁止 `:latest`**；AGENTS 要求"镜像按 digest 引用"，
   但无 daemon/registry 访问无法解析 digest，故每处留
   `# TODO(digest,EXT-08)`，在可运行环境补 `@sha256:` 后移除 TODO（已写入部署手册）。
   api/web 用多阶段 Dockerfile（构建上下文=仓库根；BuildKit cache mount 与
   `*.Dockerfile.dockerignore`）。
5. **配置与密钥**：全部环境变量走 `deploy/compose/.env`（模板 `.env.example`，密钥项为
   `CHANGE_ME` 占位，19 个变量与 compose 引用一一对应）；`.env` 被 .gitignore 忽略，
   仓库内无明文口令；生产建议拆 per-service secrets / Docker secrets（手册已列）。
6. **TLS 与反代**：`deploy/nginx/anesop.conf` 启用 TLS 1.2/1.3、HSTS、
   `X-Content-Type-Options`、`X-Frame-Options`、CSP（占位注释）、gzip、SPA fallback、
   `/api/` 反代保留 Host/X-Forwarded-*；证书目录 `deploy/nginx/certs/` 只放 README，
   真实证书由院方挂载（不入库）。
7. **静态校验代替运行时校验**：`scripts/compose-check.sh` 纯 Python/YAML 校验
   32 项（服务齐全、healthcheck、depends_on 条件、tag 非 latest、端口暴露面、卷、
   `.env` 键覆盖、无明文口令、Dockerfile FROM pin、nginx TLS/安全头/SPA/反代），
   Docker daemon 可达时追加 `docker compose config -q`，否则打印 `EXT-08` 跳过；
   实测 168 ms、PASS 32 / FAIL 0 / SKIP 1。**该脚本暂不并入 `scripts/check.sh`**，
   避免与并行任务改同一文件，后续集成轮统一纳入门禁。
8. **备份恢复**：`docs/deploy/backup-restore.md` 定 PG 每日全备 + WAL 归档、MinIO
   版本化、恢复演练步骤与 RPO/RTO 目标；实际演练待可运行环境（人工/EXT-08）。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| Kubernetes 清单 | 单院 30 间手术间规模用 Compose 足够，K8s 运维成本高（方案 §3.3.5） |
| 镜像 tag 直接写死 digest 占位 | 伪造 digest 会导致拉取失败且不可验证；用 TODO 显式登记更安全 |
| 密钥直接写 compose environment | 违反"密钥不入库"；统一走 .env + CHANGE_ME |
| 默认启动监控栈 | 增加资源占用与暴露面；用 profile 按需启动 |
| 现在就 `docker compose config` 校验 | 无 daemon；由脚本在可用时自动补，避免伪造通过 |

## 后果（正面/负面/代价）

- 正面：单院部署拓扑、依赖顺序、健康检查、暴露面、密钥与 TLS 基线一次成型；静态门禁
  可重复、可在 CI 运行；构建产物与运行时镜像可复现（多阶段 + pin tag）。
- 负面：**未实测**（无 Docker）；digest 未补；api 镜像未构建（Checkstyle/依赖下载未在
  镜像内验证）；nginx 证书与 TLS 未实测；监控 scrape 需补
  `micrometer-registry-prometheus`（api 当前 `/actuator/prometheus` 会 404）；备份恢复
  未演练。
- 代价：部署仍需人工签字（AGENTS 上线闸门），自动施工不执行生产部署；Web 容器需挂载
  真实证书才能启动 HTTPS。
- 解除条件（EXT-08）：宿主机提供可用 Docker daemon → 补 digest、跑 `docker compose
  config/up`、补镜像扫描与备份演练，并把 compose-check 纳入 CI。
