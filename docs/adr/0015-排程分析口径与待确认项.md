# ADR-0015 排程分析口径与待确认项

- 关联：M2-M6-01 / 方案书 §2.4.2/§2.7.2 / D-14（运营 T+1）/ D-21（系统出数、绩效规则院方另定）

## 背景与约束

M2-M6-01 交付排程分析：术间利用率、准点开台率、取消率与脱敏导出。方案书要求
"排程分析：术间利用率、准点开台率、取消率"，但未冻结分子/分母、首台定义、时区与
停诊日处理；M1 生产代码尚无"实际开台/结束"写入路径（术中状态由 M3/HIS 回写）。
导出 CSV 若不做公式注入防护，可能被 Excel/Sheets 执行（含主数据字符串列）。

## 决策

1. **时间口径**：所有统计按 `Asia/Shanghai` 自然日；`from/to` 必填、跨度默认上限
   **92 天**（配置 `anesop.m1.analytics.max-range-days` 只允许收紧，配置 >92 时夹紧为 92
   并 WARN，契约描述与实现一致）。
2. **术间利用率**：`Σ计划手术时长 / Σ术间可用时长`。当前分子为**计划时长**（系统内尚无
   实际占用时长），分母包含区间内术间日历可用时长；计划 vs 实际口径、未来日/停诊日是否
   计入分母——**【待确认】**（Q-3，蓝图 §2.7.2 表述为"占用时长"）。
3. **准点开台率**：首台 = **当日最早计划台次**；首台取消/未开始 → 该日不纳入评估
   （单列"未评估天数"，避免把第二台当首台抬高指标）；实际开始时间依赖 M3/HIS 回写，
   当前系统内数据不足时前端显示"暂无数据"而非 0.0%（Q-1/Q-2）。
4. **取消率**：`区间内取消台次 / 区间内总台次`，按原因码分组；分母含已取消台次。
5. **导出脱敏**：CSV 仅聚合值与术间/科室/原因码，不含患者姓名/住院号/证件/手机号；
   单元格以 `=`/`+`/`-`/`@`/制表符/回车开头时前置单引号并引号包裹（CSV 公式注入防护）；
   UTF-8 BOM；导出留痕 ANALYTICS_EXPORT（detail 无 PHI）。
6. **数据范围**：DEPT 用户只看本科室术间、ROOM 用户只看绑定术间、未绑定 403；
   科室下拉从分析响应派生，不依赖 `m1:schedule:read`（质控角色可查看分析）。
7. **权限**：`m1:analytics:read` 授予 SYS_ADMIN/SYS_OR_MANAGER/SYS_QC_MANAGER（V12
   data-only 迁移，无 DDL）。
8. **待确认（必须回写）**：
   - Q-1：实际开台/结束时间由 M3 术中记录或 HIS 回写，当前系统内无写入路径；
   - Q-2：首台取消/未开始是否"不评估"还是"判延误"；
   - Q-3：利用率计划/实际口径、停诊日/未来日处理；
   - 运营时效 T+1 与实时看板的差异（D-14）在 M8 驾驶舱统一。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 前端直接调 `/rooms` 获取科室下拉 | 需 schedule:read，质控角色无权限且异常被吞；改为分析响应派生 |
| CSV 限制字符白名单 | 主数据可能合法含 `-`/`+`（如术间编号）；前置单引号是业界通用防护且不改变值 |
| 准点率分母含未开始首台 | 会低估/高估且口径不可解释；不评估 + 单列更透明 |
| 现在就接 HIS 实际开台 | 无接口环境（EXT-01）；M3/HIS 回写后再切换口径 |
| 把配置上限开放到 366 | 大区间全表聚合风险不可控；上限 92 天与契约一致 |

## 后果（正面/负面/代价）

- 正面：指标口径可解释、时区/边界固定、导出防注入、权限最小、待确认项集中；
  data-only 权限迁移不引入表变更。
- 负面：当前准点率/利用率实际可用性受 M1 数据限制（多数为"暂无数据"）；口径仍待院方
  确认；V12 是为权限点新增的迁移（无 DDL），后续角色权限调整需继续用 data-only 迁移。
- 代价：每次口径调整需评审并同步契约/README；CSV 防护需覆盖所有导出列。
- 解除条件：院方确认 Q-1…Q-3；M3/HIS 回写实际开台时间；D-14 驾驶舱时效统一。
