# ADR-0018 药品字典、麻精判定与五专日结口径

- 状态：已接受（班次/日结汇总/分类字典等临床与财务口径待确认）
- 日期：2026-11-14
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策；不确定口径标【待确认】）
- 关联：M4-M15-01 / M3 T-4 / 方案书 §2.5（药品与耗材、麻精五专）/ §3.4 / §3.9.2 /
  §3.9.3 / AGENTS 临床规则与审计红线

## 背景与约束

1. M3 遗留 T-4：麻醉记录用药的 `narcotic` 由**客户端声明**，舒芬太尼等误报 `false` 即可
   绕过双人核对（`docs/modules/m2/README.md` §10 已登记风险）。M4 必须收口。
2. 方案书 §2.5 要求麻精五专（专人/专柜/专册/专账/专处方），但未给出班次、差异容忍度、
   日结数据来源等可执行口径；直接猜临床/财务规则违反 H-04/H-06。
3. 药房系统对接属 EXT-02：当前无接口规范、无网络策略、无测试环境（Docker 亦不可用），
   真实对接不可行。
4. 契约优先：新增 `drug.yaml 0.1.0`（additive），迁移 V20 仅新增 schema/表/权限/校验。

## 决策

1. **麻精判定的唯一权威是药品字典**（T-4 收口）：
   - `m4-api` 暴露只读 `DrugDictionaryService`（`findById` / `findByName`）；
   - 名称解析顺序固定：药品名称 → 通用名 → 别名（trim + 忽略大小写），**归一化后必须唯一**；
     命中多个不同药品时 fail-closed（409/422 `DRUG_AMBIGUOUS`），禁止 `LIMIT 1` 静默取；
   - M2 用药登记以字典为准：未收录 400、字典歧义 422、声明与字典不一致 400
     （**不采用“取并集/取客户端”**）、字典 `narcotic=true` 强制双人核对；
   - **归一化唯一（2026-11-14 复审 B-1）**：`drug.name`、`drug.generic_name`（非空）、
     `drug_alias.alias` 均按 `trim + lower` 唯一；创建/更新反向校验“名称/通用名不得撞他人
     别名、别名不得撞他人名称/通用名”，冲突 409。没有这条唯一性，按名称判定就会歧义，
     因此它是判定机制的组成部分，而不仅是体验优化。
2. **药品目录全院可读、维护收敛到药房/管理员**（`m4:drug:read` /
   `m4:drug:write` 授予 SYS_ADMIN、SYS_PHARMACIST）；新增最小角色 SYS_PHARMACIST（V20），
   只授予登录 + 药品域权限，避免自助扩权。
3. **五专按科室/角色限制（最小实现）**：五专记录带 `department_id`，复用 m0 数据范围
   （ALL 全院；SITE 院区子树；DEPT 授权组织；SELF 按本人所属科室推导；ROOM 不适用五专，
   fail-closed 403），不新增数据范围模型。写入时服务端校验科室存在、启用且 `org_type=DEPT`；
   前端必须显式选择科室，禁止用当前用户标识冒充科室。麻精护士不授予五专维护，避免
   “既给药又记账”。
4. **专册/交接/日结 append-only**：只 INSERT，UPDATE/DELETE/TRUNCATE 一律 SQLSTATE 55000；
   更正只能新增记录。理由：麻精账是法定留痕，允许改历史等于允许抹账。
5. **双人签字必须不同人**：专册/交接两名签字人不同（400 + DB CHECK）；交接另要求
   交班人 ≠ 接班人。本期不校验签字人是否在职/持权限（M2 的双人核对已有该能力，五专
   签字按“现场纸质/工牌代签”口径最小实现，见 Q-3）。
6. **日结只做恒等校验，不自动汇总**：校验 `期初 + 入库 − 使用 − 退回 = 期末`；不平时 409
   并返回 `details`（期望值/实盘值）；不平不落库；同一柜 + 业务日 + 班次唯一。
   不设差异容忍度、不从基数/专册自动推算（避免臆造财务口径）。日结重开/调整机制未实现
   （append-only 只能新增记录），登记为 Q-10。
7. **基数随柜、科室不可变（复审 B-2）**：`drug_baseline` 的 `department_id` 由数据库守卫
   保证不可改；upsert 时校验 `existing.departmentId` 与请求一致且在调用者可见范围，
   跨科改写 409、不可见科室 403。
8. **EXT-02 为 SIMULATED**：状态端点执行无外部 I/O 的模拟探测并留痕；失败降级为
   “本地字典可用 + degraded=true”，不阻塞临床记录；不返回/保存外部凭据与处方明细。
9. **审计白名单**：五专审计不含处方号原文、人员姓名与患者标识；药品审计不含备注原文；
   关键操作失败路径（400/409/422）以独立事务写 `result=0` 审计（S-2），便于追溯误操作。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 保留客户端声明、字典只做提示 | T-4 风险不收敛：误报 false 仍可绕过双人核对 |
| 客户端与字典不一致时取客户端值 | 判定权威不确定，审计不可追溯 |
| 用药记录直接存 `drugId` 并强关联 | anesthesia.yaml 契约不在本任务写域；先按名称解析，后续 additive 增 `drugId` |
| 五专记录可编辑/可撤销 | 麻精账允许改即允许抹账，违反法定留痕 |
| 日结自动汇总基数 + 专册 | 入库/退回来源单据未定义，会臆造财务口径 |
| 五专把 SELF 一律拒绝 | 麻醉医师默认 SELF 范围，全部拒绝会让临床无法使用；改为按本人所属科室推导（S-5），ROOM 仍拒绝 |
| 新增独立数据范围模型 | 方案书未定义，M4 阶段不值得引入第二套权限语义 |

## 后果（正面/负面/代价）

- 正面：T-4 风险关闭（服务端判定 + 集成用例）；药品目录与五专有明确权限/审计/留痕；
  日结平账可解释、可复核；适配器失败不阻塞临床。
- 负面：按名称解析依赖字典命名纪律（改名/别名冲突会拒绝录入）；五专签字人资格未校验；
  日结仍需人工申报数据，差异调查靠线下流程，重开/调整未实现（Q-10）；真实药房对接未验证；
  抢救用药（M2 抢救记录）仍为自由文本、未接字典（Q-9）。
- 代价：V20 迁移 + m4 模块 + 前端两页 + 契约生成/门禁接线；后续补 `drugId` 关联、班次
  三班制、分类字典、差异审批与真实适配器需新增迁移/契约版本并再评审。

## 复审修订（2026-11-14，M4-M15-01 独立评审）

- **B-1 T-4 闭合**：名称/通用名/别名归一化唯一 + 反向冲突 409；字典解析多候选
  409/422 `DRUG_AMBIGUOUS`；补真实 PG 用例（别名指向麻精 + 声明 false、大小写/空白、歧义）。
- **B-2 基数跨科**：`existing.departmentId` 一致性 + 可见范围校验；`department_id` DB 守卫不可变。
- **B-3 科室必选**：新增 `GET /v1/narcotic/departments`；前端显式选择，移除用户 ID 回退；
  服务端校验科室存在/启用/`DEPT`（400/422）。
- **S-1/S-2**：M2 用药审计键拆 `administrationId` + `dictionaryDrugId`；M4 失败路径写
  `result=0` 审计（REQUIRES_NEW，无 PHI）。
- **S-3/S-5**：append-only TRUNCATE 用例、真实 PG 解析用例；SELF 按本人所属科室推导。
