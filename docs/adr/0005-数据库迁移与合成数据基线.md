# ADR-0005 数据库迁移与合成数据基线

- 状态：已接受
- 日期：2026-11-12
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策）
- 关联：S0-06 / 方案书 §3.4「领域模型与数据设计」/ §3.9.1–3.9.3 / D-04 / EXT-08

## 背景与约束

S0-06 要求 Flyway V1 基线（用户/角色/权限/审计/字典）、Testcontainers 集成测试、
回滚说明，验收"空库迁移成功、重复执行幂等、升级路径 V1→V2 通过、测试容器可在 CI 跑"。
约束：Docker 不可用（EXT-08），Testcontainers 无法实跑；home 只读；字段与表名不得
臆造（须有 §3.4/§2.4.1 依据）；测试只能用 SYNTHETIC 数据；迁移遵循 expand-contract、
不可逆脚本需回滚说明。方案未规定主键类型、schema 划分细节、种子策略，按 §3.4.3
与 AUTONOMY §2 决定。

## 决策

1. **schema 按模块划分**：M0 使用 `m0_platform` schema（§3.2.2 表 3-2 数据归属），
   PG 专有类型（uuid/jsonb/inet）、plpgsql 触发器集中于此，便于 D-04 信创适配时
   集中映射；跨模块关系保持逻辑外键，M0 内部关联表用物理 FK。
2. **主键与时间**：主键 `uuid PRIMARY KEY DEFAULT gen_random_uuid()`（PG13+ 内核函数，
   无需 pgcrypto）；所有时间列 `timestamptz`；服务端时间（NTP 校验留 S0-07+）；
   审计四件套 `created_at/by`、`updated_at/by`；软删 `deleted boolean`；乐观锁
   `version bigint`。命名：表名单数、`idx_/uk_` 前缀（§3.4.3）。
3. **审计 append-only（等保要求）**：`sys_audit_log` 无 `updated_at/deleted`，用 plpgsql
   函数 + 3 个触发器拒绝 UPDATE/DELETE/TRUNCATE（SQLSTATE 55000），在线留存 ≥6 个月；
   审计字段含 actor/action/resource/result/detail(jsonb)/ip(inet)/user_agent/trace_id/
   occurred_at。按月分区与 MinIO 归档（§3.4.4）延后到 M4/M6，届时用受控维护流程
   与删除台账。触发器由表 owner 持有，`ALTER TABLE ... DISABLE TRIGGER` 属 DBA 受控
   操作（迁移脚本不授予业务账号 DDL 权限，见 docs/db/README）。
4. **迁移拆分与纪律**：V1 = 结构初始化（8 表、8 PK、7 CHECK、6 FK、6 业务唯一索引 +
   10 普通/部分索引，全部带中文注释）；V2 = SYNTHETIC 种子。迁移一经合入不可修改，
   变更新增 V 脚本（expand-contract）；**forward-only**，回滚 = 备份恢复或前向修复，
   不提供 undo 脚本（Flyway 社区版也无 undo）；不可逆语句需在 PR 声明并附演练记录。
5. **SYNTHETIC 种子与生产红线（评审 B-1 修复后）**：
   - `db/migration/V2` 只含平台预置基线：6 角色（SYS_ADMIN/ANESTHESIOLOGIST/
     NURSE_ANESTHETIST/SURGEON/OR_MANAGER/QC_MANAGER）、17 权限（8 基础 + m0..m8:access）、
     42 条角色授权、6 类 22 项字典；**不含任何演示账号**。
   - 演示管理员 `demo_admin`（`must_change_password=true`，BCrypt `$2y$10$`）独立放在
     `db/seed/demo/V100__demo_admin_synthetic.sql`，是**独立 Flyway location**，仅
     dev/test 加载；生产 `spring.flyway.locations` 只允许 `filesystem:/opt/anesop/db/migration`。
     独立评审 blocking B-1 的根因是演示账号随 `db/migration` 进入生产镜像（公开口令可在
     生产登录），修复后测试两条路径分别断言：生产路径 `sys_user=0`、无 demo_admin；
     演示路径 demo_admin 存在且 BCrypt 匹配。
   - 所有角色/权限/字典为平台预置基线，生产实施按院方岗位矩阵调整；无真实姓名/工号/手机号。
   - **S0-07 必须落地**：prod profile 启动断言拒绝 `demo_*` 账号（否则拒绝启动）。
6. **测试基座（无 Docker）**：集成测试用 **Zonky 嵌入式 PostgreSQL 16.15.0**
   （Apache-2.0 + PostgreSQL License，已在根 pom 管理），真实执行 Flyway 与 MyBatis；
   Testcontainers 仍为 EXT-08（保留版本管理，不实跑）。**25 个测试**（bootstrap 7 +
   m0-impl 18）：空库迁移、幂等、V1→V2 升级、种子断言、append-only（UPDATE/DELETE/
   TRUNCATE 均断言失败）、forward-only（无 U 脚本）、版本连续、生产/演示两条 locations
   路径、JSONB/INET TypeHandler 往返、逻辑删除、乐观锁、大小写不敏感用户名唯一、
   CHECK 拒绝非法状态、工号部分唯一。测试改为结构性断言（不硬编码表数/时间列数/脚本清单）。
7. **持久层骨架**：m0-impl 增 6 实体 + 6 Mapper（MyBatis-Plus，`@TableName("m0_platform.x")`、
   `@TableId`、口令哈希 `@JsonIgnore`、`@TableLogic` 软删、`@Version` 乐观锁）；主键 UUID
   采用 `IdType.INPUT`，并提供 `UuidTypeHandler`（MyBatis 3.5.16 无内建 UUID 处理器）；
   `JsonbTypeHandler`/`InetTypeHandler` 处理 `jsonb`/`inet`（评审 S-3）。**S0-07 插入前必须
   赋值 UUID，并全局注册 TypeHandler**；`MapperScan`、Flyway 运行时装配、审计字段自动
   填充、事务与权限在 S0-07 落地（已登记）。
8. **多院区维度延后**：§3.4.5/D-01 要求数据模型保留院区维度，但 V1 未含
   `tenant_id/site_id`。一期单院（A-01），多院区上线前按 expand-contract 增加
   `site_id`（nullable + 索引）并重建 `username` 等唯一索引；风险与步骤写入
   `docs/db/README.md` §8。此为**接受的风险**，不是遗漏。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| bigint 自增主键 | 采集网关离线补传与跨系统合并需要全局唯一、不可枚举 ID；UUID 更合适 |
| 审计用应用层保障 append-only | 数据库层强制更可靠（防应用缺陷/误操作），满足等保"不可删除" |
| 审计表按月分区立即落地 | 需要归档任务与运维流程，M4/M6 落地更划算；当前索引 + 触发器满足读写 |
| H2 跑迁移测试 | H2 为 MPL-2.0（白名单外）且 jsonb/部分索引/plpgsql 不兼容，会掩盖 PG 行为 |
| 种子直接内置生产管理员 | 违反最小权限与真实数据红线；演示账号强制改密且文档标注 |
| 现在就加 site_id | 一期单院，且字段/口径未定（D-01/Q-01），过早固化反增迁移成本 |

## 后果（正面/负面/代价）

- 正面：M0 数据基线一次成型且带中文注释；审计不可删由数据库强制执行；迁移测试真实
  跑 PG16；种子可复现且全合成；演示账号与生产迁移彻底隔离（评审 B-1 修复）；用户名
  大小写不敏感唯一、审计对象维度索引、jsonb/inet 映射与软删/乐观锁均有测试；
  未来多院区有明确 expand 路径。
- 负面：mvn verify 约 3 分钟（嵌入式 PG 启动 + 25 个测试），check.sh 约 4–5 分钟，
  超出 S0-03 的 3 分钟目标 → 由 S0-04 在 CI 拆 job 并行解决（本地仍为全量门禁）；
  审计分区/归档、多院区字段、Testcontainers 实跑均待后续；触发器与部分索引需信创库
  等价实现。
- 代价：嵌入式 PG 首次下载约 14.7 MB 二进制（已缓存 `.m2repo`）；实体 UUID 赋值与
  运行时装配留给 S0-07，若遗漏会在集成时暴露。
