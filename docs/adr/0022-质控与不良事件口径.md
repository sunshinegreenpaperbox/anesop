## 背景与约束

M4-M17-01 交付质控指标、不良事件 RCA、病历质量抽查与上报导出。方案书要求“指标自动生成、
可钻取复核、可上报，不良事件闭环”，并明确三条底线：**分子分母可追溯到原始记录条目**、
**上报后 48 小时内完成分级初评**、**规则变更留版本、跨期指标按当期版本计算**；但未冻结
指标清单/阈值、上报格式、匿名化与闭环时限。同时存在四条硬约束：

1. 指标数据分散在 M2 排程台次、M3 麻醉记录单/术前访视/三方核查、M4 麻精专册与高值耗材流水；
2. AGENTS 禁止跨模块访问对方数据表/Mapper，也不允许 m4 反向依赖 m1-api/m2-api 形成模块环；
3. I-10 外部上报平台不可用（EXT），本期只能提供占位导出，不能编造平台字段映射；
4. 质控留痕是质量追溯证据，不能被“改数”抹平；同时不良事件/整改又必须能闭环。

## 决策

1. **指标版本化与版本选择**：指标定义按 `code + version` 存 `m4_qc.qc_indicator`，语义/阈值
   变更必须新增版本行（数据库守卫禁止原地改口径/阈值/身份列/是否计入达标统计，只允许
   `ACTIVE→RETIRED`；`DELETE`/`TRUNCATE` 由触发器拒绝 55000，防止删定义抹掉追溯链）。
   查询按**有效期**选择版本：`effective_from <= to AND (effective_to IS NULL OR
   effective_to >= from)`；同一 `code` 在查询周期内**只允许一个生效版本**，版本区间重叠
   → **409**（fail-closed，不静默取一条；查询接口在契约中以 `x-allow-query-conflict: true`
   显式声明该冲突，避免被“409 仅限状态变更”规则误判）。查询区间跨版本时按有效期切分为多段，每段使用
   当期版本独立计数并留存（结果 `period_from/period_to` 为切分后的真实统计区间），
   **不把两个版本合并成一个值**。结果按 `指标 + 版本 + 周期 + 科室` 唯一留存于
   `qc_indicator_result`；重算覆盖同一快照的分子/分母/值/计算时间，**跨版本历史结果独立
   保留**，不回溯重写。时区固定 `Asia/Shanghai`，查询周期为本地日期闭区间、跨度 ≤ 366 天
   （超过 400）。
2. **指标清单与阈值【待确认】**：V25 落地 **7 条合成参考指标**（`QC-SYN-*`，`provisional=true`），
   覆盖结构/过程/结果并声明 `data_source`：
   - `QC-SYN-STRUCT-001` 麻醉记录单完成率（M3 记录单 + M2 排程）；
   - `QC-SYN-PROC-002` 术前访视完成率（M3 访视 + M2 排程）；
   - `QC-SYN-PROC-003` 三方核查完成率（M3 三方核查 + M2 排程）；
   - `QC-SYN-PROC-004` 麻精专册双人签字**结构合规率**（M4 麻精专册；结构类，仅衡量登记
     字段完整性，不代表术中实时双人核对行为；`inTargetStatistics=false`，Q-1 确认前
     **不计入达标统计**）；
   - `QC-SYN-OUT-005` 不良事件上报率（本域不良事件 + M2 排程，每千台次）；
   - `QC-SYN-PROC-006` 病历质量抽查合格率（本域病历抽查，合格线 90%）；
   - `QC-SYN-STRUCT-007` 高值耗材 UDI 使用登记率（M4 高值耗材流水）。
   这些**不是**国家/省级正式指标，也不代表院方最终阈值；正式目录确认后以新版本行替换
   （code 不变、version 递增），不修改本批行（Q-1）。
3. **计算规则**：`value = round(numerator / denominator × 100, 2)`（`PERCENT`）或
   `× 1000`（`PER_1000_CASES`）；`denominator = 0` 时 `value = 0` 且 `targetMet = false`
   （不判达标、不做除零），并保留 `denominator = 0` 供数据质量复核。
   达标判定 `GTE`（≥ 阈值）/`LTE`（≤ 阈值）；`inTargetStatistics=false` 的指标即使达到
   阈值也固定 `targetMet = false`（仅展示值，不进达标统计）。分子/分母由服务端从声明的
   数据源计数，**不接受客户端传入**；未登记编码按 0/0 呈现“无数据”，不静默丢弃。
4. **只读跨模块投影放在装配层**：指标计数通过 m4-api 端口 `QcIndicatorSource` 获取，由
   `api-bootstrap` 的 `QcIndicatorSourceAdapter` 执行 5 条**只读 SELECT**（台次/麻精/不良事件/
   抽查/高值耗材），不复制 m1/m2/m3 的 Mapper/实体，不写任何模块的表；数据范围由
   `QcIndicatorFilter` 表达，非全院且 `orgIds` 为空时直接 403（fail-closed，不退化全表）。
   `scheduleId`/`recordId` 的逻辑关联校验通过独立端口 `QcCaseReferenceSource` 执行 2 条
   只读 SELECT（排程/记录单 → 手术申请科室）：不存在/已删除 **422**、属他科 **403**。
5. **不良事件状态机**：`REPORTED → RCA → RECTIFYING → CLOSED`，**只允许逐级前进**；
   越级、跳级、重复闭环一律 409。`POST /adverse-events/{id}/rca` 仅 `REPORTED` 可提交
   （一条事件一条 RCA）；`POST /rca/{id}/close` 是**分阶段闭环**：阶段 1 复核（事件 →
   RECTIFYING）、阶段 2 确认整改完成（事件 → CLOSED）。阶段 1 提前声明完成、阶段 2 缺
   `rectificationCompleted=true`、已闭环再闭环均 409；复核人不得为上报人/责任人（422）。
   是否要求双人复核、复核人资质（质控专员/科主任）【待确认】（Q-5）。
6. **append-only 留痕**：`adverse_event` 业务内容、`adverse_rca`/`rectification` 全文内容不可
   改删；只有状态机字段可一次性前移，复核/闭环字段只允许从 NULL 写入一次；数据库触发器
   兜底 `55000`（UPDATE/DELETE/TRUNCATE 与非法状态迁移均拒绝）。更正只能新建事件/整改并
   说明关联号；生产运行账号不得拥有 DDL 权限（否则可禁用触发器）。
7. **病历质量抽查**：评分项白名单四项 `COMPLETENESS`/`TIMELINESS`/`SIGNATURE`/`CONSISTENCY`，
   1–12 项且编码不重复；每项 `0 ≤ score ≤ maxScore ≤ 100`；总分/满分/等级/缺陷由服务端计算
   （不接受客户端传总分）；`score < maxScore` 视为缺陷且必须填写脱敏缺陷说明；
   合格线 **90%**、等级 A≥95/B≥90/C≥80/D<80（**待确认**，Q-4）。整改一条抽查一条，
   提交后抽查 `OPEN→RECTIFYING`，复核闭环后 `→CLOSED`；复核人不得为整改责任人。
8. **脱敏与上报占位**：本域不存患者标识；不良事件描述为**已脱敏文本**，服务端按固定规则
   拒绝疑似标识（身份证/住院号/手机号关键词或连续 11–19 位数字）→ 400；抽查缺陷说明同样
   拦截。导出 CSV 为 UTF-8 BOM、防公式注入、**不输出描述/根因/整改等自由文本原文**，
   只输出标识/类型/等级/状态/时间/科室/计数与院内在册人员姓名。导出上限 **50000 行**：
   以 `LIMIT 50000+1` 探测，超限**不截断**并返回 **422**；失败审计仍写 `QC_EXPORT`
   （result=0，detail 含真实 `dataRows`、`truncated=true`、`limit`）。I-10 平台的字段映射、
   文件格式与上报周期未确认，本期只提供 **EXT 占位 CSV 模板**，不直连外部系统（Q-2）。
9. **匿名上报【待确认】**：`anonymous=true` 时对外只返回“匿名上报”，内部仍保存上报人标识
   供追溯与独立复核校验；是否允许对质控专员也匿名待院方确认（Q-3）。
10. **闭环时限【待确认】**：方案书要求 48h 内完成分级初评；本期只记录状态与时间，不内置
    超时拒绝（避免把未确认时限写成硬规则），由看板/报表提示超期（Q-6）。
11. **权限与数据范围**：V25 新增 `m4:qc:read`/`m4:qc:write`/`m4:qc:review`/`m4:qc:export`，
    最小授予 SYS_ADMIN（四项）、SYS_QC_MANAGER（四项）、SYS_OR_MANAGER（read+write）。
    数据范围：`ALL` 全院、`SITE`/`DEPT` 按科室；`ROOM`/`SELF`/无范围 403（质控为科室/全院
    聚合口径，不做个人质控视图）；`deptId` 越界 403；单对象越界/不存在 404。
    审计：`QC_INDICATOR_QUERY`/`QC_INDICATOR_COMPUTE`/`ADVERSE_EVENT_*`/`RCA_*`/
    `CHART_REVIEW_*`/`RECTIFICATION_*`/`QC_EXPORT`，detail 不含 PHI 与自由文本原文。

## 影响

- 正向：指标可追溯到原始记录计数且口径版本可追溯，定义禁删/禁清空（55000）；不良事件/
  整改状态机与 append-only 让质控留痕不可篡改；导出无 PHI、无自由文本，满足“数据不出院”
  红线；分阶段闭环让“复核”与“整改完成确认”责任分离。
- 代价：`GET /v1/qc/indicator-results` 与导出会按请求重算并写结果快照（幂等 upsert），
  高频调用会带来写放大；查询周期跨版本时同一 `code` 返回多段结果（每段一个版本/区间），
  前端与导出需按 `periodFrom/periodTo` 展示而非假定单行；暂不做缓存/物化视图，待正式指标
  目录与调用频率确认后再评估。
- 兼容：qc.yaml 0.1.0 为首个版本，baseline 同步落地；后续只做 additive 变更。
- 回滚：应用下线 `/v1/qc/*` 与前端菜单；库层 DROP 语句、权限删除顺序与归档要求见
  `docs/db/README.md` §4.20（不良事件/RCA 属质量追溯留痕，回滚前必须导出归档）。

## 【待确认】（院方/医务处/质控办确认后升版本）

- Q-3 匿名上报范围（是否对质控专员匿名）与内部追溯留存的可见性。
- Q-4 病历抽查评分项权重、合格线与等级划分。
- Q-5 复核人资质与是否要求双人复核；复核人与上报人/责任人的回避范围。
- Q-6 分级初评 48h 与整改闭环时限是否作为硬校验（超时拒绝/仅提示）。
- Q-7 指标钻取明细（到患者/记录条目）的权限与脱敏方案。
- Q-8 质控指标结果的锁定/归档策略（是否允许重算历史周期）。
- Q-9 病历抽查规则：方案书要求按规则抽样（比例/分层/重点病历）；本期**降级为人工抽检**
  （由抽查人逐份录入四项评分），不做随机/分层自动抽样、不做抽样比例与必查清单的硬校验，
  待质控办确认抽样规则后实现（当前不影响抽查评分与整改闭环）。
- Q-10 复核人/责任人身份关联：`reviewerName`/`responsibleName` 目前为**自由文本**（≤64），
  未与 m0 用户表建立外键/工号关联，无法自动校验复核人资质或“是否本人在册”；本期以
  “复核人不得等于上报人/责任人”的文本比对做最小独立性校验，属**已知取舍**，待院方确认
  是否改为用户选择 + 资质校验（Q-5 相关）。
