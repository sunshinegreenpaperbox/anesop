# ADR-0014 知情同意、CA 签名占位与三方核查口径

- 状态：已接受（临床/法务口径部分待确认）
- 日期：2026-11-13
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策；合规口径标注待确认）
- 关联：M2-M5-01 / 方案书 §2.4.3 / §3.9.4 / D-05 / EXT-05

## 背景与约束

M2-M5-01 实现知情同意（模板、签署、拒绝、撤销）、三方核查/Time-out（申请维度）与
锁单前置接口。CA 厂商与证书不可用（EXT-05），真实签名无法在本环境验证；方案书要求
"记录单 CA 签名、纸电并行 2 周"（D-05），且知情同意与三方核查属临床/合规高风险。
方案未逐条规定模板版本策略、有效同意语义、签署人权限与 Time-out 项集合。

## 决策

1. **模板不可变 + 可停用**：`consent_template` 内容 append-only（UPDATE/DELETE/TRUNCATE
   由 DB 触发器拒绝）；通过 `status`（ACTIVE/RETIRED）+ `retired_at` 与新端点
   `POST /consent-templates/{id}/retire` 停用旧版本；历史同意记录仍引用原版本。模板内容
   变更必须发新版本（`UNIQUE(template_code, version)`）。
2. **同意状态机**：DRAFT → WAITING_SIGN → SIGNED（或 DECLINED）；SIGNED 可一次性 REVOKED
   （必须带原因）。签署人姓名/关系/方式为留痕字段，**任何状态均不可改写**（DB 守卫）。
   签署必须针对 ACTIVE 申请；重复签署未撤销的同意 409；`POST /sign` 只允许
   WAITING_SIGN/DRAFT 状态。
3. **有效同意语义（S-6）**：同一申请**最多一条有效 SIGNED 同意**（部分唯一索引强制），
   撤销后（REVOKED）不占位，可重新签署；下游 M3 取"最新有效 SIGNED"。模板选择默认只允许
   最新生效版本（Q-2 待医务处确认是否强制）。
4. **CA 签名占位（EXT-05）**：签名只落 `signature_ref` + `signature_hash`（摘要输入不含
   姓名等标识），`ca_status=SIMULATED`；**不构成法律有效签名**，UI/文档显式标注；
   真实 CA 接入（签名/验签/时间戳/证书链）待院方 CA 厂商 SDK，接口保持可替换。
5. **三方核查**：申请维度 `three_way_check` append-only（DB 触发器 + `check_version`），
   记录 Time-out/Time-out 人、Sign-out/Sign-out 人、标本/植入物核对、问题项；新版本默认
   继承上一版本 Time-out 时间，避免"有效 Time-out 时间被静默后移"（S-1）；未核查时
   `isThreeWayCheckCompleted=false`（fail-safe），M3 锁单时强制校验。
6. **权限最小化**：`m2:consent:read|write`、`m2:threeway:read|write` 授予
   SYS_ADMIN/SYS_ANESTHESIOLOGIST/SYS_NURSE_ANESTHETIST；"知情同意告知是否限麻醉医师"
   待医务处确认（Q-3）。失败路径（409/422）同样写审计（result=0，无 PHI）。
7. **待确认（必须回写）**：
   - Q-1：同意有效期（术前 24 小时？）、超期/术式变更是否重新知情、撤销后是否通知术者/
     排程并阻断开台；
   - Q-2：是否只允许最新生效模板版本签署；
   - Q-3：知情同意告知是否限麻醉医师（当前护士角色可创建/签署）；
   - Q-4：Time-out 是否需逐项确认身份/部位/术式/过敏史/影像（当前仅标本/植入物 + 问题）。
8. **上线闸门**：知情同意/签名/核查属临床与合规高风险，生产启用前须医务处/法务确认
   第 7 条并签字；自动施工阶段仅以 SYNTHETIC 数据验证流程与技术约束。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 允许模板 UPDATE 修正内容 | 破坏留痕与"同一版本内容一致"；改为停用 + 新版本 |
| 应用级"最新同意"靠 UI 约定 | 下游 M3 可能读到错误版本；用部分唯一索引强制 |
| 存签名原文/图片 | PHI 与法规风险；只存 ref/hash，原文由 CA/文件系统按权限管理 |
| 三方核查直接覆盖更新 | 无法追溯；append-only + 版本 |
| 现在就接真实 CA | 无厂商 SDK/证书（EXT-05）；占位接口保持可替换 |

## 后果（正面/负面/代价）

- 正面：同意与核查全链路可追溯、不可篡改；CA 占位与真实接入解耦；有效同意语义明确；
  临床待确认项集中登记。
- 负面：模板停用需新端点与状态列；签名不具法律效力（EXT-05）；Time-out 项集合偏少；
  护士权限边界待医务处确认；M3 锁单联动尚未实现（仅暴露 fail-safe 集成点）。
- 代价：V11 迁移与触发器复杂度上升；每次模板/核查口径变更需评审；真实 CA 接入需适配
  签名/验签/时间戳与证书校验。
- 解除条件：CA 厂商 SDK 与证书（EXT-05）；医务处确认 Q-1…Q-4；M3 完成记录维度核查与
  锁单前置强制校验。
