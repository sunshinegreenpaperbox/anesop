# ADR-0019 人员档案、分级授权、排班与培训口径

- 状态：已接受（R1–R5 映射、班次定义、术间多人、职称字典等临床/管理口径待确认）
- 日期：2026-11-14
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策；不确定口径标【待确认】）
- 关联：M4-M13-01 / 方案书 §2.4.4（M3 人员管理）/ §3.4.1（人员与资质限界上下文）/
  §3.4.2（人员 1:N 授权、排班）/ §3.9.2（RBAC 与数据权限）/ AGENTS 临床规则与审计红线

## 背景与约束

1. 方案书要求“资质可查、排班可排、授权可控、绩效有据”，并明确关键规则：
   **无授权不得执行对应麻醉方式或术式，排程与记录两处校验；证书到期前 30 天提醒；
   排班变更须审批并留痕**。
2. 方案书**没有**给出 R1–R5 的业务含义、级别 → 术式/年龄/ASA 的映射、职称/职级字典、
   班次（两班/三班/日结班结双轨）、术间是否允许同时多人、换班审批流等可执行口径；
   直接猜临床授权规则违反 H-04/H-06。
3. 人员主数据权威源归 AD（方案书 §3.5“人员归 AD，本系统只维护映射表与冲突提示”）；
   一期没有 AD 接口，档案暂由本系统维护，`userId` 与 m0 用户关联（非空时一人一档案）。
4. 契约优先：新增 `staff.yaml 0.1.1`（additive），迁移 V21 新增
   schema/表/索引/约束/触发器/视图/权限点、V22 新增授权治理列/角色，不改写 V1–V21。

## 决策

1. **R1–R5 不内置临床映射**：`level` 是审批人录入的级别标签，
   **授权范围以显式字段为权威**（`surgeryScopes`、`ageMin/ageMax`、`asaMax`、有效期）。
   理由：映射属临床资质决策，方案书未定义；内置映射会把“系统猜测”变成执业依据。
   院方确认授权目录后，可通过配置 `anesop.m4.staff.authorization.level-policies`
   叠加“级别上限”校验（授予超限 422、校验返回 `LEVEL_POLICY_EXCEEDED`），无需改表或契约。
2. **授权历史 append-only**：每次授予/复评/撤销写入新 `version`（1 起递增），历史只增不改；
   UPDATE/DELETE/TRUNCATE 一律 SQLSTATE 55000（触发器兜底）；当前版本取 version 最大的一行
   （视图 `staff_authorization_current`），撤销后当前版本 `status=REVOKED`，旧版本保留。
   理由：分级授权是执业资格留痕，允许改历史等于允许抹掉“谁在何时批准了什么”。
3. **授权校验返回全部原因**：`POST /v1/staff/authorization-checks` 返回 `allowed` 与
   多原因（未授权/已撤销/未生效/过期/术式超范围/年龄超范围/ASA 超上限/离职/级别策略超限）；
   离职人员一律拒绝。**判定通过不表示临床适宜**，最终由麻醉医师判断（H-06）。
   进程内集成（M1 排程 / M5 术中）用 `StaffAuthorizationService.evaluate`，不依赖 HTTP 上下文。
4. **排班冲突按“人员 + 日期 + 班次”和“术间 + 日期 + 班次”双唯一**（仅 PLANNED 占用名额；
   取消保留记录并释放名额）。409 返回 `details[]`（`staffId`/`roomId` + 冲突排班标识）。
   班次枚举 `DAY/NIGHT/ON_CALL` 对应方案书“日常班/值班/备班”（**三班制/节假日班【待确认】**）。
   已取消排班不可复活（409 + 数据库守卫 55000）。
5. **培训到期提醒默认 30 天**（方案书口径）：`expiresOn <= 今天 + days`（含已过期，便于清零），
   `status` 按固定 30 天窗口计算 VALID/EXPIRING/EXPIRED/NO_EXPIRY；完成日期不得晚于今天、
   到期不得早于完成日期；同一人员同一课程编码唯一。
6. **数据范围复用 m0，不新增权限模型**：ALL 全院 / SITE 院区子树 / DEPT 授权科室 /
   SELF 仅本人（按 m0 userId；**写操作 403**，避免本人自改科室/职称/授权）/ ROOM 与无范围
   fail-closed 403。单对象越界与不存在统一 404（不泄露存在性）。
7. **权限最小集（V22 修正）**：`m4:staff:read`（SYS_ADMIN / SYS_OR_MANAGER /
   SYS_AUTH_MANAGER / SYS_ANESTHESIOLOGIST）、`m4:staff:write`（SYS_ADMIN /
   SYS_AUTH_MANAGER）、`m4:staff:authorize`（SYS_ADMIN / SYS_AUTH_MANAGER）、
   `m4:schedule:manage`（SYS_ADMIN / SYS_OR_MANAGER）、`m4:training:manage`
   （SYS_ADMIN / SYS_AUTH_MANAGER）。新增 **SYS_AUTH_MANAGER**（`data_scope=DEPT`，绑定科室
   后按科室维护档案/培训并审批授权）；`SYS_ANESTHESIOLOGIST` 收敛为**只读**。理由：评审 B-2
   指出麻醉医师同时持有人员写权限职责过宽，且授权审批缺少独立岗位；按科室隔离可避免跨科越权。
   不授予麻醉护士/术者人员域权限（需要时按岗位另行评审）。
8. **审计白名单**：`STAFF_CREATE/UPDATE`、`AUTH_GRANT/REVOKE`、
   `SCHEDULE_CREATE/UPDATE/CANCEL`、`TRAINING_RECORD`；detail 只含标识、工号、科室、
   枚举与日期摘要，**不含姓名、证书号原文与联系方式**；失败路径（400/409/422）以独立事务
   写 `result=0` 审计（复用 M4FailureAuditor）。
9. **人员档案不做物理删除**：`employmentStatus=INACTIVE` 表示离职/停用，档案只读历史，
   授权校验一律 `allowed=false`（不得执业）；工号/userId/创建留痕数据库守卫不可改。

10. **授权治理（评审 B-1）**：授予/撤销禁止自授（`staff.userId == caller` 403）；`approvedBy`
    必须存在、启用、具备 `m4:staff:authorize`，且不是操作者/被授权人（伪造/停用 400，
    无权限/自审 403）；`R1/R2`、范围 `*` 或 `ASA>=4` 必须两名**不同**审批人，双方标识与
    审批时间落库。理由：授权是执业资格决策，单人可自批等于没有审批。
11. **撤销时点与回溯（评审 B-4 / Q-21）**：撤销写入新 REVOKED 版本并记录 `revoked_at`，
    **不追溯既往**；回溯判定按 `approved_at <= at AND valid_from <= at AND
    (revoked_at IS NULL OR revoked_at > at)` 取当时生效版本，而不是最新版本。理由：补录/复盘
    必须回答“当时是否有授权”，不能让后来扩大或撤销的范围改写历史；若院方要求追溯到生效日，
    走 Q-21 确认后另立迁移/契约并补红冲流程。
12. **资质状态不参与授权判定（评审 S-3 / Q-20）**：`staff_qualification.status/valid_to`
    当前只用于档案展示与到期提醒，V22 以注释纠正 V21 的过强表述；是否新增
    `QUALIFICATION_INVALID` 并阻断授权待医务处/人事确认。理由：方案书未定义“哪类资质是
    执业前置条件”，系统不臆造临床规则（H-04/H-06）。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 内置 R1–R5 → 术式/ASA 默认映射 | 方案书未定义，臆造映射会成为执业依据（H-04/H-06） |
| 授权记录可编辑/可撤销覆盖旧行 | 资质与授权留痕可被抹除，无法回答“当时谁批准了什么” |
| 撤销时删除旧版本、只留最新 | 同上；撤销本身应可追溯，故写入 REVOKED 新版本 |
| 排班冲突只在数据库报错 | 前端无法展示冲突明细，运维排障困难；改为服务层 409 + details，唯一索引兜底 |
| 已取消排班允许改回 PLANNED | 会让“取消/恢复”绕过审批与审计；改为新建排班 |
| 人员业务归 m3 schema | 任务卡明确 V21 使用 `m4_staff`；M4 管理域统一承载 E-M13，避免一期跨域拆库 |
| 新增独立数据范围模型 | 方案书未定义第二套权限语义，复用 m0 的 ALL/SITE/DEPT/SELF 足够 |

## 后果（正面/负面/代价）

- 正面：无授权不得执业在服务端可校验（排程/术中一个集成点）；授权历史可追溯；排班冲突
  可解释、可展示；培训到期可提醒且含已过期清零；权限/数据范围/审计口径与 M4 既有域一致。
- 负面：R1–R5 未内置映射，等级本身不产生约束（需院方配置策略或人工录入范围）；换班审批流
  未实现（只有变更/取消留痕）；术间多人排班不支持（唯一索引限制）；AD/人事接口未接，
  档案需人工维护；资质为替换式维护（不保留历史），历史变更只能靠审计摘要回溯。
- 代价：V21 迁移 + m4-api/impl + 4 个前端页面 + 契约生成/门禁接线；后续确认口径后需新增
  迁移/契约版本（三班制、术间多人、换班审批、资质历史、绩效基础数据）并再评审。

## 待确认（必须回写）

- Q-1 **R1–R5 映射**：各级别的业务含义、可实施术式范围、年龄段与 ASA 上限的默认值；
  是否按级别固定 ASA 上限、是否需要“值班资质/独立值班年限”（方案书 §2.4.4）。
- Q-2 **ASA 上限与 ASA VI**：本域只纳入 ASA1–ASA5（ASA VI 不纳入），院方是否要求 ASA VI
  或“急诊 ASA”特殊口径。
- Q-20（评审 Q-1）**资质吊销/过期是否阻断授权**：当前不参与判定；是否要求执业资格
  `REVOKED`/过期即拒绝并新增 `QUALIFICATION_INVALID` 原因码，待医务处/人事确认。
- Q-21（评审 Q-2）**撤销是否追溯**：当前撤销不追溯既往（`revoked_at` 之后拒绝）；是否要求
  回溯到授权生效日、是否需红冲/补正流程与审批留痕，待医务处确认。
- Q-3 **班次定义**：两班/三班/日结 + 班结双轨、节假日班、备班（ON_CALL）是否占用术间。
- Q-4 **术间多人**：同一术间同一班次是否允许麻醉医师 + 护士同时排班（当前唯一索引只允许一人）。
- Q-5 **换班审批流**：换班申请、科主任/手术室审批、通知与撤销流程（当前只有 PUT/取消留痕）。
- Q-6 **资质历史**：执业资质是否必须保留历史版本（当前替换式维护，仅审计摘要可回溯）。
- Q-7 **AD/人事接口**：人员主数据同步方向、频率、冲突处理与离职联动（方案书 §3.5 I-12）。
- Q-8 **职称/职级/术式字典**：目前职称/职级为自由文本、术式为字符串编码，待院方字典确认后
  改为字典项与白名单校验；术式字典归属 M1/M0。
- Q-9 **绩效基础数据**：例数/台次/时长/难度系数/夜班加班是否在本域统计（当前只做排班，
  统计归 M4-M16-01）。
- Q-10 **授权校验集成落点**：M1 排程创建/调整与 M5 术中记录在何时调用 `evaluate`
  （排程即拦 vs 术中提示）、拒绝后的覆盖审批流。
