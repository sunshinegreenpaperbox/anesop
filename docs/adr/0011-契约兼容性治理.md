# ADR-0011 契约兼容性治理：字段删除、弃用窗口与基线评审

- 状态：已接受
- 日期：2026-11-13
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策；M2-M1-01 独立评审 blocking B-1 触发）
- 关联：S0-05/ADR-0003、M2-M1-01、AGENTS「契约优先与数据变更」

## 背景与约束

M2-M1-01 在 patient.yaml 0.3.0 中删除了 `idCardMasked`、`phoneMasked`、`inpatientNo`
三个响应字段（出于患者数据最小化），并把 baseline 同步覆盖为当前版本，使
`scripts/contract-check.sh`（baseline→current）通过。独立评审用 **HEAD 的旧 baseline**
复跑 oasdiff，得到 5 个 `response-required-property-removed` error，判定为违反 AGENTS
"字段只增不删；删除或改类型升 major、双写过渡并写 ADR"。结论：这是流程缺陷
（baseline 覆盖掩盖破坏性变更），不是单纯字段争议。

## 决策

1. **版本与变更类型**：OpenAPI `info.version` 采用语义化版本。
   - additive（新增路径/可选字段/新错误码等）→ **minor**；
   - 删除字段/端点、收窄枚举、类型变更、必填性收紧 → **major**，且必须：
     ADR + 兼容说明 + 弃用窗口（≥1 个里程碑）+ 双写/过渡方案（若涉及数据）。
2. **弃用窗口**：需要移除的字段先标 `deprecated: true` 并在 description 写明
   "计划在 1.0.0 删除"，保留字段定义（可不填充/返回 null），至少一个里程碑后再删。
   本任务即按此恢复 `idCardMasked`、`phoneMasked`、`inpatientNo`（0.3.0），
   删除统一推迟到 1.0.0 major。
3. **baseline 评审纪律**：`packages/contracts/openapi/baseline/` 只能在该契约变更
   **通过独立评审后**同步；评审必须用"上个已发布 baseline（HEAD 版本）"复跑 oasdiff，
   不能只看工作区 baseline（否则破坏性变更被自证通过）。该步骤写入 review 简报与
   `docs/api/README.md` §7。
4. **PHI 与查询参数**：患者姓名/住院号等 PHI 不得出现在 GET query（会被 nginx/代理/
   访问日志与浏览器历史记录）。检索类接口优先 **POST + JSON body**；既有 GET 保留但标
   `deprecated` 且生产禁用（nginx `/api/` 访问日志去除 query），新增
   `POST /v1/patients/search` 作为正式入口。
5. **契约破坏性变更的额外检查**：S0-04 CI 的 `ci/contract` 与本地 `contract-check.sh`
   在 baseline 更新时仍按新 baseline 比对；**评审子代理**负责用旧 baseline 复跑并
   给出结论（本 ADR 落地后该要求写入 M2/M3 任务卡模板）。
6. **自动化落地**：`scripts/contract-check.sh` 第 3 步在 git 可用时自动用 HEAD 中的
   baseline 快照复跑 oasdiff（`--fail-on WARN`），失败即红；本地 `scripts/check.sh` 与 CI
   `ci/contract` 均走该脚本，评审纪律不再只靠人肉执行。
7. **0.3.0 的处置**：patient/scheduling 均保持 0.3.0（additive：新增端点、
   deprecated 字段保留）；不升 major；不删除字段；不覆盖未评审 baseline。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 直接接受 0.3.0 删除并升 1.0.0 | 契约尚无生产消费者，但 AGENTS 要求 major + ADR + 双写；且 baseline 覆盖掩盖问题必须先纠正 |
| 保留字段但返回真实证件号/手机号 | 违反患者数据最小化；改为 deprecated + 不填充 |
| 只改文档、不改 baseline 流程 | 同类问题会重复发生；必须把"旧 baseline 复跑"写进评审纪律 |
| 用 POST 替换 GET 并直接删除 GET | 删除属破坏性；GET 保留 deprecated，生产禁用 |

## 后果（正面/负面/代价）

- 正面：契约演进有明确版本/弃用窗口；baseline 不再能"自证通过"；PHI 不再经 GET
  query 进日志；患者数据最小化与兼容性同时满足。
- 负面：deprecated 字段会保留到 1.0.0，契约存在"空字段"；GET 检索仍需生产禁用与
  运维约束；每次契约变更多一次旧 baseline 复跑步骤。
- 代价：1.0.0 时需一次性 major 清理 deprecated 字段并回归；评审模板需增加检查项。
- 解除条件：1.0.0 交付前执行 major 清理（删除 deprecated 字段/端点），并更新
  baseline、TS/Java 生成物与消费方。
