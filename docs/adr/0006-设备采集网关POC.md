# ADR-0006 设备采集网关 POC（协议、缓冲、幂等与时间校正）

- 状态：已接受
- 日期：2026-11-12
- 决策人：自动施工代理（按 AUTONOMY §2 默认决策）
- 关联：S0-09 / 方案书 §3.6「设备数据采集」/ 铁律 4 / EXT-04 / EXT-08

## 背景与约束

S0-09 要求：模拟设备（TCP/串口）→ 解析 → 标准化 → 入库；断网本地缓存 ≥4h；幂等补传；
健康检查。验收"1 台模拟设备端到端 10 分钟数据不丢；断网 5 分钟后恢复自动补传且不重复；
监控指标可见"。真实设备协议与采集盒待定（D-06/EXT-04）；Docker 不可用（EXT-08）；
方案未规定网关内部实现细节，按 AUTONOMY §2 决定并记录。

## 决策

1. **网关为独立 Spring Boot 进程**（`services/device-gateway`，parent=根 POM，暂作为根
   reactor 模块之一；部署单元与业务应用分离，符合"三个部署单元"铁律）。POC 用 **Java
   原生 ServerSocket + 虚拟线程**（30 间连接量级足够，零额外依赖）；生产建议 Netty
   （BSD-3，引入前需 ADR + 白名单），不现在引入。
2. **模拟协议 v1（POC 专用）**：TCP 行帧，`DEV|deviceId|seq|measuredAt|hr|spo2|nibpSys|
   nibpDia|etco2|temp|quality`，UTF-8、`\n` 分隔，`-` 表示缺省；非法帧丢弃并计数。
   真实协议适配（HL7v2/厂商 SDK/串口/MQTT）列入 EXT-04，待 D-06 设备清单后一设备一适配器。
3. **五段流水线**：TcpDeviceServer → FrameParser → VitalNormalizer（单位/范围/质量/时钟）
   → LocalBuffer → VitalUploader（JDBC）。缓冲为按设备 JSONL 文件 + fsync + 大小/时间
   轮转 + `ack.json` 原子写入，容量 64 MiB/设备（≈66 小时 @1Hz），超限淘汰最旧段并计数；
   进程重启可恢复未确认记录。上传失败保留缓冲 + 指数退避（500ms→30s）；幂等由数据库
   唯一键 `(device_id, seq, measured_at)` + `ON CONFLICT DO NOTHING` 保证。
4. **时间戳三条规则（§3.6.3）的实现取舍**：`measured_at` **永远保存设备原值**，它是幂等键
   的组成部分；时钟偏差只计算并写入 `measured_at_corrected`，偏差类型记
   `quality_flags(ts:FUTURE/ts:SKEW/ts:BACKFILL)`。POC 中先尝试"直接改写 measured_at 做
   校正"导致补传重放产生新时间、幂等失效——已修正并作为设计红线：**幂等键字段不得被
   校正逻辑改写**。
5. **入库模型**：`m2_anes.anesthesia_vital` 一帧一行、体征分列（唯一键一帧一唯一；行式
   metric_code/value 会让同帧多体征互相冲突）；append-only，纠错走后续修订表
   （expand-contract 说明写在 V4 SQL 内）。`synthetic boolean` 标记合成数据。
6. **可观测性**：actuator health 暴露 gateway 组件（buffer/uploader/tcp 明细；DB 不可达
   或连续失败 ≥3 置 DOWN，暂停置 OUT_OF_SERVICE）；micrometer 指标
   `gateway.frames.received/invalid/buffered/uploaded/duplicate/failed`、
   `gateway.buffer.pending.records(.total)`、`gateway.buffer.evicted.segments` 等。
   未引入 Prometheus registry（需登记白名单；S0-04/M6 再补 /actuator/prometheus）。
7. **测试（无 Docker）**：Zonky 嵌入式 PostgreSQL 16 真库；39 个测试（解析 11、标准化 10、
   缓冲 6、退避 3、重试 1、幂等 1、配置 4、E2E 3）。E2E 用加速时间模拟 10 分钟 660 帧，
   断言 received=uploaded=660、duplicates=0；断网 5 分钟用"暂停上传 + 5 分钟数据窗口"
   模拟，恢复后 300 行、重放 duplicates=300 但表行数不增；重启恢复缓冲后全部入库。
8. **根 POM 集成**：本次提交在根 `pom.xml` 增加 `services/device-gateway` 模块（主会话集成
   动作），使 `mvn verify` 覆盖网关；SpotBugs 模块级 exclude 仅排除构造器注入误报
   `EI_EXPOSE_REP2`（另有真实 `IS2` 缺陷已修复），其余缺陷仍会失败。

## 备选与放弃理由

| 备选 | 放弃原因 |
|---|---|
| 用 H2/SQLite 做本地缓冲 | 需要与 PG 语义一致的幂等验证；文件队列 + 真库测试更接近生产 |
| 直接把设备时间改写为校正时间 | 破坏补传幂等（POC 实测），改为双列 |
| 行式 metric_code/value 表 | 一帧多体征会冲突，读写放大；分列更贴合采集场景 |
| POC 即引入 Netty | 增加依赖与复杂度，30 连接原生 socket 足够；Netty 留 M2 演进 |
| 网关 HTTP 契约（device.yaml） | POC 直连 PG，无平台间 HTTP 接口；M2 接入管理台时再定契约 |
| 用 Docker/Testcontainers 验证 | 环境不可用（EXT-08）；用嵌入式 PG 代替，Testcontainers 版本保留 |

## 后果（正面/负面/代价）

- 正面：端到端不丢数、断网补传不重复、重启恢复、可观测，全部有真实测试；时间校正不破坏
  幂等；V4 与 V1/V2 联合迁移通过。
- 负面：TCP 无 TLS/认证（仅限本机/隔离 VLAN，生产必须补）；PGSimpleDataSource 无连接池
  （生产需 Hikari，依赖待登记）；无死信队列、无波形存储、仅单协议；Netty/多协议/设备
  协议均待 D-06/EXT-04；Prometheus registry 未引入。
- 代价：网关测试 39 个、verify 约 1:40（含嵌入式 PG）；根 reactor 增加一个模块。
- 解除条件：D-06 设备清单与协议确定 → 一设备一适配器 + 协议一致性测试；生产部署补
  TLS/认证/连接池/告警规则；EXT-08 解除后补容器化与镜像扫描。
