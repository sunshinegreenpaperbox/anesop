# ANESOP 应急预案（六类场景）

> 原则：**临床优先、止血优先、证据优先**。每类场景固定六段：检测信号 → 止血动作 →
> 回滚/切换 → 通知链 → 恢复验证 → 留痕。
> 通用分级/流程见 [`README.md`](README.md)；联系人见 [`CONTACTS.md`](CONTACTS.md)；
> 回滚细节见 [`../deploy/ROLLBACK.md`](../deploy/ROLLBACK.md)；备份恢复见
> [`../deploy/backup-restore.md`](../deploy/backup-restore.md)。
> **本手册不含真实患者数据/口令/密钥**；所有命令示例中的 `<...>` 由值班按院方环境替换。

## 0. 通用"先做/禁做"

| 先做 | 禁做 |
|---|---|
| 记录时间、影响范围、症状、traceId（脱敏） | 未确认就整机重启数据库/批量重启 |
| 保临床：纸质记录/电话通知/人工核对 | 删除日志、清空队列、覆盖备份 |
| 止血：停导出、停写入、切只读、回滚、隔离账号 | 在生产执行逆向 SQL、手工改业务数据 |
| 升级：不确定就打电话，不猜 | 把患者信息发到外部模型/个人网盘/微信群 |

## 1. 数据库故障（PG 不可用/主库宕/磁盘满/复制断）

### 1.1 检测信号

- API `/actuator/health` 为 `DOWN` 或 5xx 激增；日志出现 `Connection refused`、
  `connection timeout`、`too many connections`、`could not extend file`；
- `pg_isready -h <pg> -p 5432` 非 `accepting connections`；
- 主备复制延迟/中断告警；磁盘使用率 >90%；备份/WAL 归档失败。

### 1.2 止血动作

1. 公告"数据库故障"，临床转纸质/离线记录（按院方纸质应急预案）；
2. 停止非必要写入：停导出/报表/批量任务；必要时停 API（`systemctl stop anesop-api` 或
   `docker compose stop api web`），避免连接风暴；
3. 检查：磁盘、连接数、PG 日志、主备状态；**不要**反复重启 PG；
4. 主库可恢复（如连接数/锁）：限流/杀阻塞会话需 DBA 执行并留痕；
5. 主库不可恢复：DBA 按主备切换或 PITR（见 [`backup-restore.md`](../deploy/backup-restore.md)）。

### 1.3 回滚/切换

- 应用不回滚（数据库问题优先切库/恢复）；应用版本问题另按 §2；
- 主备切换：提升备库 → 更新连接串/VIP → 启动 API；
- PITR：停写 → 保留现场 → 恢复 → 校验 → 启动；RTO ≤30 min、RPO ≤5 min。

### 1.4 通知链

DBA/信息科值班 → 信息科负责人 → 项目经理 → 医务处/手术室（P1，电话+企业微信）。
数据丢失风险时同步信息安全负责人。

### 1.5 恢复验证

- `pg_isready`、`/actuator/health` UP、登录成功；
- `flyway_schema_history` 完整、关键表行数、最新业务时间、审计连续；
- 关键路径：申请/排程/记录单可读写；采集补传幂等；
- 与临床核对纸质记录，补录并标注（不覆盖原始时间）。

### 1.6 留痕

事故单：故障起止、影响台次、切换/恢复步骤、RTO/RPO、数据损失窗口、操作人、证据
（PG 日志、监控截图、校验 SQL 输出）。**不记录患者身份明细**。

## 2. 应用不可用（API 宕/502/504/启动失败）

### 2.1 检测信号

- nginx 502/504 激增；`/healthz` 可开但登录失败；`/actuator/health` 超时/非 UP；
- 进程 `failed`/容器 `unhealthy`/重启循环；OOM、端口占用、配置/密钥加载失败；
- 发布后立即出现（回滚信号）。

### 2.2 止血动作

1. 确认范围：单实例/全实例；是否刚发布/改配置/换证书；
2. 先回滚到上一版本（[`ROLLBACK.md`](../deploy/ROLLBACK.md) §3），不要现场改代码；
3. 单服务重启：`systemctl restart anesop-api` 或 `docker compose restart api`（一次，不循环）；
4. 临床转纸质；入口保留 `/healthz`，错误页不暴露堆栈/配置；
5. 保留现场：日志、`systemctl status`、`docker compose ps`、最近变更。

### 2.3 回滚/切换

- 应用回滚 ≤10 分钟：jar/镜像 tag/静态资源；nginx 配置回滚后 `nginx -t` + reload；
- 多实例：摘除异常实例，保留健康实例；不要全部同时重启；
- 配置/密钥错误：从口令管理系统取上一版本，禁止临时放宽 `prod` 守卫。

### 2.4 通知链

发布负责人/信息科值班 → 项目经理 → 临床（P1）；安全相关（越权/泄露）加信息安全。

### 2.5 恢复验证

健康 UP、登录、关键路径冒烟、审计写入、采集补传；观察 30 分钟错误率/P95。
回滚后确认版本号/镜像 tag 为上一版本。

### 2.6 留痕

发布单/回滚记录：触发时间、版本、回滚步骤、恢复时间、根因初判、后续修复项。

## 3. 采集断连（设备/网关离线、补传失败）

### 3.1 检测信号

- 看板/设备列表 `OFFLINE` 增多；`lastSeenAt` 超过阈值（默认 120s）；
- ingest 401/404/5xx；网关缓冲增长；补传批次 `duplicateBatch/qualityFlags` 异常；
- 单台设备/单术间/全网段（区分设备、网关、网络、平台）。

### 3.2 止血动作

1. 临床继续手动记录生命体征/事件，不等待采集；
2. 检查网关电源/网线/交换机/端口、设备串口/协议、令牌是否轮换；
3. **不要**清空网关缓冲、不要删平台已收批次；保留现场；
4. 平台侧不要重启 API 来"修采集"（会扩大影响）；
5. 区分：设备故障 vs 网关故障 vs 网络分区（§5）vs 平台 401/404。

### 3.3 回滚/切换

- 备用网关/采集盒切换（如配置）；设备转手动；
- 网络恢复后网关按**同一 batchKey** 补传（幂等），不要生成新批次重复上报；
- 平台侧核对 `acceptedRows/duplicateRows/rejectedRows` 与质量标记。

### 3.4 通知链

手术室/麻醉科 → 信息科值班 → 设备厂商/网关负责人（P1 若全断；单台 P2）。

### 3.5 恢复验证

- 设备 `ONLINE`、`lastSeenAt` 更新；时间轴连续、补传标记 `ts:BACKFILL` 正确；
- 重放同一批次：第二次 `acceptedRows=0`、`duplicateBatch=true`（可用
  `scripts/drill-offline-replay.sh`）；
- 与手动记录核对缺口，必要时补录并注明来源。

### 3.6 留痕

断连起止、影响设备/台次、补传批次键与结果、质量标记、厂商工单号。不含患者标识。

## 4. CA 不可用（签名失败/超时/证书问题）

### 4.1 检测信号

- 锁单/签名接口超时/5xx；签名状态失败；CA 服务健康检查失败；
- 证书过期/链不完整；CA 厂商维护公告。

### 4.2 止血动作

1. **禁止伪造/代签/跳过签名**；记录"待签名"清单（受控，不含明文患者信息）；
2. 临床按院方"纸电并行"预案：纸质签名 + 系统记录，待 CA 恢复后补签；
3. 锁单是否可继续由医务处/麻醉科按制度决定；系统不得静默放宽；
4. 检查网络/证书/CA 服务；联系 CA 厂商；不要重启数据库；
5. 若为本地配置/证书问题，按变更单修复并留痕。

### 4.3 回滚/切换

- 备用 CA/离线签名（如院方批准）；切换前确认签名有效性与审计；
- 恢复后按待签名清单逐条补签，保留原记录时间与补签时间；
- 不得用测试证书/模拟签名替代生产签名（EXT-05 未解除前须明确标注）。

### 4.4 通知链

医务处/麻醉科 → 信息科 → CA 厂商 → 项目经理（P1）；涉及签名有效性按 P0 评估。

### 4.5 恢复验证

- 新签名成功、证书链/时间戳正确；历史签名摘要可验证；
- 待签名清单清零或登记遗留；审计含补签动作；
- 抽查锁单记录签名与修订链。

### 4.6 留痕

CA 故障时段、影响记录数（受控清单）、补签时间/操作人、厂商工单、医务处决策。

## 5. 网络分区（临床区 ↔ 应用区/数据库断）

### 5.1 检测信号

- 部分区域无法访问、其他区域正常；监控出现双向上报/心跳丢失；
- 网关缓存增长；API 时通时断；DNS/VLAN/防火墙变更后出现；
- 警惕"双主"写入/重复数据。

### 5.2 止血动作

1. 确认分区边界（哪些术间/终端/网关受影响），公告；
2. 受影响区域转纸质/离线；**停止跨区写入**，避免双写；
3. 保留网关缓冲；不要删除/重建库；不要同时提升两个主库；
4. 网络组排查交换机/防火墙/VLAN/路由；变更回滚（如刚改网络）；
5. 数据库主备保持单主；分区恢复前不做双向同步。

### 5.3 回滚/切换

- 网络变更回滚到上一配置；
- 恢复后先只读验证，再开放写入；
- 补传/补录按时间顺序，冲突以原始记录为准并留说明；
- 如发生双写，按业务主键去重/对账，禁止盲目覆盖。

### 5.4 通知链

信息科网络组 → 信息科负责人 → 项目经理 → 临床（P1）；跨院区链路同步运营商。

### 5.5 恢复验证

- 双向连通、延迟正常；API/DB/Redis/RabbitMQ/MinIO 健康；
- 数据对账：台次/记录/事件无重复/丢失；审计连续；
- 采集补传幂等；时钟一致（NTP）。

### 5.6 留痕

分区起止、影响范围、网络变更单、对账结果、补录/补传清单。

## 6. 疑似数据泄露（PHI 外发/越权/异常导出）

### 6.1 检测信号

- 异常导出（大量/非工作时间/非授权账号）、DLP/防火墙告警；
- 账号异常登录/共享、越权 `ACCESS_DENIED` 激增；
- 日志/截图/工单出现患者标识；外部模型/网盘/邮件传输告警；
- 第三方/厂商侧报告数据外发。

### 6.2 止血动作（**30 分钟内上报**）

1. **立即停止**：停导出/停相关账号/断外链/封禁终端网络（按预案）；
2. **保留证据**：日志、审计、导出文件哈希、终端镜像、聊天/邮件记录；**不删除**；
3. 隔离：禁用账号/撤销会话/轮换可能泄露的密钥（按信息安全负责人指令）；
4. 评估范围：数据类型（姓名/住院号/手机/临床文本）、人数、接收方、是否出院；
5. 上报：信息安全负责人 + 项目经理（30 分钟内），按院方制度报医务处/合规；
6. 对外沟通统一由信息安全负责人/院方出口，个人不得发布。

### 6.3 回滚/切换

- 不"回滚"数据泄露；以 containment + 证据 + 整改为主；
- 若由缺陷导致（越权/导出未脱敏），回滚到上一版本或关闭相关功能；
- 修复后复核权限矩阵、导出脱敏、审计覆盖，再恢复功能。

### 6.4 通知链

发现人 → 信息安全负责人（30 分钟内）→ 项目经理 → 医务处/院方合规 →（按法规）监管；
涉及外部厂商同步其安全接口人。**不通过微信群传患者信息**。

### 6.5 恢复验证

- 泄露通道关闭、账号/密钥处置完成；
- 审计可还原访问链；受影响对象清单（受控）；
- 整改项（权限/脱敏/日志/培训）完成并复核；
- 经信息安全负责人确认后方可恢复相关功能。

### 6.6 留痕

安全事件单：发现/上报时间、数据类型与范围、处置动作、证据清单/哈希、通知对象、
整改与复查结论；按等保要求保留 ≥6 个月（或院方更长期限）。

## 7. 演练与更新

- 每类场景至少每年演练一次；上线前至少演练：数据库故障、应用回滚、采集断连、疑似泄露；
- 演练用 [`../deploy/DRILL-RECORD-TEMPLATE.md`](../deploy/DRILL-RECORD-TEMPLATE.md) 记录；
- 组织/联系人/系统版本变化后 5 个工作日内更新本手册与 [`CONTACTS.md`](CONTACTS.md)；
- 演练失败或连续两次失败升级 P1，暂停相关发布。
