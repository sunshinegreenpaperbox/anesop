# 方案基线（V1.0 冻结）

> 冻结日期：2026-11-12。冻结对象：《手术麻醉信息系统 · 施工前方案书 V0.9》+ 第 7 章全部建议方案。
> 冻结后，除"推翻已决项"流程外，不再讨论方案；施工按本基线执行。

## 1. 冻结内容

| 项 | 基线结论 |
|---|---|
| 建设范围 | M0 公共支撑 + M1–M8 八大模块，单院私有化，先临床闭环后管理域再驾驶舱 |
| 试点假设 | 1 家三甲、30 间手术间（含 2 间杂交/介入）、年约 3.5 万例；一期不含日间手术与分院区（原 D-01 建议） |
| 架构 | 模块化单体 + 契约优先 + 独立采集网关；微服务只作演进选项（D-03 建议） |
| 后端 | Java 21 LTS + Spring Boot 3.4 + MyBatis-Plus + Flyway + PostgreSQL 16（D-02 已决） |
| 前端 | Vue 3.5 + TypeScript 5.6 + Element Plus + Vite + Pinia + ECharts |
| 数据库与信创 | PostgreSQL 16 开发；SQL 保持可移植，国产库适配列为二期（D-04 建议） |
| 电子签名 | 记录单与麻醉总结 CA 签名，纸电并行 2 周，具体 CA 厂商以接口文档为准（D-05 建议） |
| 设备采集 | 麻醉机/监护仪/输注泵/BIS/肌松/血气 6 类；采集盒项目采购；POC 先 1 台（D-06 建议） |
| 集成 | HIS/EMR/LIS/PACS/护理/药房/SPD/医保/质控平台/CA/身份/消息，按 I-01–I-14（D-08 建议） |

## 2. "全部做完"的定义（本项目验收口径）

在**无真实 HIS/设备/CA/院方环境**的条件下，V1.0 交付定义为：

1. **代码完整**：M0–M8 全部功能在本地可运行，接口、页面、数据库迁移、权限、审计齐备；
2. **测试通过**：单元/集成/契约/E2E 冒烟按 AGENTS.md 阈值；覆盖率达标；
3. **可演示**：合成数据一键初始化，能走通"申请→排程→术前→术中记录→复苏→随访→统计→质控→驾驶舱"全链路；
4. **可部署**：Compose/K8s 清单完整并通过静态校验（无 Docker 环境时以 `docker compose config` 等价检查代替，标记为环境受限项）；
5. **文档完整**：README、部署手册、运维手册、用户手册、ADR、数据字典、验收清单；
6. **可追溯**：需求/决策 → 代码/测试的追溯矩阵，已知缺陷与外部依赖清单。

**明确不在自动验收范围**：真实 HIS/EMR 联调、真实设备采集、CA 签名有效性、等保测评、性能压测达生产级、院方 UAT、临床签字。这些列为"外部依赖项"，在最终报告中逐条标注。

## 3. 冻结后的变更规则

- 技术栈、模块边界、数据模型、验收口径：变更须新建 Issue + ADR + 人工确认；
- 实现细节、目录结构、命名、测试组织：由施工代理自行决定，记入 ADR 或交接单；
- 外部依赖不可用：先做适配层与模拟器，不阻塞主线；记入 `docs/acceptance/EXTERNAL-DEPS.md`。
