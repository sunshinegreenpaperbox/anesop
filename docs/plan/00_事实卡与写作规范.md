## 2. 八大便民模块与功能分解（章节、图、目录均引用此表）

> 模块编号固定为 M1–M8，公共支撑为 M0。任何章节引用模块必须使用此编号与名称。

### M0 公共支撑（平台能力，不单列为业务模块，但必须建设）
- 统一身份认证与单点登录（对接医院 AD/LDAP/CAS）
- RBAC 角色权限、数据权限（科室/术间/患者维度）、授权分级
- 组织机构、人员、字典（术式、麻醉方式、药品、耗材、设备、术间）
- 工作流与消息中心（待办、提醒、短信/企业微信）
- 审计日志、操作留痕、字段级变更轨迹
- 报表引擎、打印模板、电子签名（CA）接入
- 接口平台（HL7 v2 / WebService / REST / MQ）、集成监控与重试
- 文件与影像存储（麻醉记录单 PDF、波形、扫描件）
- 参数配置、多院区/多手术室支持、时间同步（NTP）
- 数据备份、归档、脱敏导出

### M1 手术排程管理
1. 手术申请接收与校验（HIS/EMR 申请单、患者主索引匹配、术前检查完整性提醒）
2. 排程规则引擎：术间/台次/预计时长/优先级/急缓/隔离要求/设备依赖/医师资质匹配
3. 排程工作台：日/周视图、拖拽调整、甘特与看板、冲突实时检测
4. 急诊与加台：绿色通道、加台审批、停台/改台/换台/并台及原因登记
5. 术前准备联动：术前访视任务、禁食禁饮提醒、备血/耗材准备清单
6. 排程通知与确认：患者/家属通知、科室通知、变更通知、送达回执
7. 排程分析：术间利用率、准点开台率、取消率、平均周转时间

### M2 麻醉信息管理（术前 / 术中 / 术后）
**术前**
1. 麻醉申请审核与评估任务分派
2. 术前访视：病史、体格检查、气道评估（Mallampati 等）、ASA 分级、合并症
3. 风险评分：RCRI、Apfel（PONV）、STOP-BANG（OSA）、DASI 等（可按院方口径配置）
4. 麻醉计划：麻醉方式、气道方案、监测项目、用药与输液计划、备血
5. 知情同意：模板、谈话记录、电子/纸质签署、影像留档
6. 术前核查：WHO 三方核查（麻醉诱导前/切皮前/出室前）、禁食、过敏、牙齿、禁饮
7. 术前医嘱与用药核对、术前抗生素执行确认
**术中**
8. 麻醉记录单：时间轴自动记录、生命体征趋势（间隔可配）、事件标记（诱导/插管/切皮/拔管/出室）
9. 设备数据自动采集：麻醉机、监护仪、BIS/肌松、输注泵、血气（接口或手工补录）
10. 用药与输液：麻精药品逐次登记、微量泵、输血、出入量自动汇总
11. 预警与提醒：低血压/低氧/心动过缓/低体温/恶性高热风险、过敏与相互作用提醒
12. 气道与操作记录：插管方式、导管型号、困难气道分级、中心静脉/动脉穿刺、神经阻滞
13. 抢救与不良事件：抢救记录、麻醉相关并发症、输血反应
14. 术中核查（Time-out / Sign-out）、标本与植入物核对
15. 记录单打印、CA 签名、锁单与修改留痕（修订版本可比对）
**术后**
16. 复苏记录：入 PACU 评估、Aldrete/Steward 评分、生命体征、镇痛与并发症处理
17. 转归与出室：转病房/ICU/日间病房、交接班记录
18. 术后随访：24h/48h 随访、镇痛效果、PONV、认知功能、满意度
19. 术后镇痛：PCA 配置与随访、神经阻滞随访
20. 麻醉总结、并发症登记、质控数据自动提取

### M3 人员管理
1. 人员档案：医师/护士/技师，执业资质、职称、科室、院区
2. 分级授权：麻醉方式授权、术式授权、值班资质、独立值班年限
3. 排班管理：日常班/值班/备班、术间分配、换班审批、节假日排班
4. 培训与继续教育：学分、培训记录、考核、证书到期提醒
5. 绩效基础数据：例数、台次、时长、难度系数、夜班与加班
6. 权限与账号生命周期：入职/转岗/离职联动

### M4 耗材仓库管理
1. 耗材主数据与分类（普通/高值/植入/低值易耗）、UDI 编码
2. 入库/出库/调拨/退货，批次、效期、灭菌有效期管理
3. 术间领用与术中消耗登记（扫码/UDI 追溯、套包/术式清单）
4. 高值耗材一物一码、患者绑定、使用与计费核对
5. 库存预警、安全库存、近效期预警、盘点与差异处理
6. 供应商与证照管理（注册证、授权链）
7. 与 SPD/HRP/物资系统对接、消耗与收费对账

### M5 药品统计
1. 药品目录与麻精药品分类（麻醉药品、第一类精神药品、普通药品）
2. 麻精药品"五专"管理：专人、专柜、专册、专账、专销（处方/空安瓿/余液处置）
3. 基数管理、请领、入柜、使用登记、日结/班结、双人核对
4. 术中用药记录与医嘱执行闭环、处方与计费联动
5. 药品消耗统计：按术间/术式/医师/药品/月份，金额与数量
6. 与药房系统/合理用药系统对接，异常用药提醒
7. 报表：麻精药品使用登记表、空安瓿回收台账、季度上报

### M6 工作量统计
1. 指标口径：手术例数、麻醉例数、台次、麻醉时长、术间占用时长、加班台次
2. 维度：科室/医师/麻醉方式/ASA 分级/术间/时段/院区
3. 绩效口径配置：权重、难度系数、二次分配规则（可按院方方案配置）
4. 报表与导出（Excel/PDF）、定时生成、数据锁定与修订留痕
5. 与 DRG/DIP、手术分级、日间手术统计联动（可选）
6. 数据质量校验：漏记、重复、时间异常提示

### M7 质量控制
1. 质控指标体系：国家麻醉质控指标 + 院级指标（麻醉相关死亡率、非计划二次插管、PONV、低体温、苏醒延迟、PACU 滞留、术后镇痛不全、不良事件上报率等）
2. 指标自动计算与钻取（分子/分母可追溯至原始记录）
3. 不良事件上报、分级、根因分析（RCA）、整改跟踪（PDCA）
4. 科室质控看板、月度/季度质控报告、上报平台数据导出
5. 病历质量抽查：记录完整性、时限、签名、逻辑一致性规则引擎
6. 质控规则配置与版本管理，指标口径变更留痕

### M8 驾驶舱
1. 实时手术态势：术间状态（空闲/准备/麻醉中/手术中/复苏/清洁）、台次进度、延误预警
2. 临床风险：术前高危患者、术中预警、抢救事件、PACU 拥堵
3. 资源态势：人员到位、设备可用、耗材库存告警、麻精药品库存
4. 运营 KPI：手术量、准点开台率、术间利用率、平均住院日（联动）、取消率
5. 质量与安全：质控指标趋势、不良事件
6. 大屏适配（1920×1080 / 4K）、移动端摘要、下钻与筛选、数据时效标识

## 5. 非功能需求基线（第 2、3 章引用）

| 类别 | 指标 |
|---|---|
| 并发与容量 | 30 间手术间同时采集；在线用户 500；峰值写入 30 床 × 1Hz 级 |
| 响应时间 | 普通页面 P95 < 2s；记录写入 < 1s；驾驶舱首屏 < 3s |
| 可用性 | 核心业务 99.9%（年停机 ≤ 8.76h）；采集断网本地缓存 ≥ 4h 并自动补传 |
| 数据保留 | 麻醉记录/病历按病历管理要求长期保存（≥30 年）；波形原始数据 ≥ 1 年（可配置） |
| 安全 | 等保三级；传输 TLS；存储加密（敏感字段）；审计日志 ≥ 6 个月；权限最小化 |
| 合规 | 电子病历应用水平分级 5 级目标；《电子签名法》；数据分类分级与脱敏 |
| 可维护性 | 模块化单体、契约优先、可观测（日志/指标/链路）、一键部署与回滚 |
| 兼容性 | Chrome/Edge 最近两个大版本；1366×768 起；打印 A4；国产 OS/浏览器适配（若信创） |
| 性能基线 | 排程页 1000 条手术记录加载 < 2s；月度工作量报表 < 10s |

**推荐理由（供第 3 章展开）**：Java/Spring 在医院私有化交付、中间件生态、运维接管与人才供给上最稳；Vue 3 + Element Plus 在表单密集的医疗后台开发效率与 AI 生成友好度平衡最好；PostgreSQL 的 JSONB、分区、扩展能力适配波形与半结构化数据，且可平滑迁移国产库。所有版本号以 2026-11 时点稳定版为准，实施前锁定并写入依赖白名单。

## 7. 架构原则（第 3 章必须遵守，不得写成微服务全家桶）

1. **模块化单体优先**：按 M0–M8 划分 Maven 模块与前端路由包，模块间只通过应用服务接口/领域事件通信，禁止跨模块直接访问对方表。
2. **契约优先**：OpenAPI、数据库迁移脚本、领域模型先评审后编码；前后端以契约并行开发。
3. **采集与业务解耦**：设备采集网关独立进程，断网缓存、补传、幂等；业务侧只消费标准化数据。
4. **临床记录不可变**：记录单锁单后修改走修订版本，保留原值与修改人/时间/原因。
5. **集成防腐层**：外部系统统一走适配器（ACL），外部字段变化不外溢到领域模型。
6. **可观测与可回滚**：每个服务有健康检查、结构化日志、关键指标；发布必须带回滚脚本。
7. **安全默认**：最小权限、敏感字段加密、导出脱敏、全量审计；患者数据不出院内网络。
8. **AI 友好**：目录结构、命名、契约、测试可被 AI 稳定检索与生成；不引入只有个别人懂的"魔法"。

## 11. Markdown 写作规范（最终由脚本转为 docx，必须严格遵守）

1. 文件开头写 `# 第 X 章 标题`（一级标题只出现一次），节用 `## X.1 标题`，小节用 `### X.1.1 标题`；节号与章号必须连续。
2. 正文用短段落（3–6 行），避免超长段落；列表用 `-`，编号列表用 `1.`；表格用标准 Markdown 管道表，首行为表头，第二行为 `|---|`（可带对齐）。
3. 图：单独一行 `![图 2-1 系统功能架构](assets/figs/fig_2_1.png)`，下一行写图注来源说明可选；图前正文必须先引用"如图 2-1 所示"。
4. 表：表前正文写"见表 X-Y"，表下一行写 `表 X-Y 表名`（用行内代码或加粗均可，脚本识别 `表 数字-数字` 开头的独立段落作为表题）。
5. 强调只用 `**加粗**`；不要用 HTML、不要用 emoji、不要用脚注语法、不要用 mermaid、不要嵌套超过两层的列表。
6. 不写"本文将……""综上所述"这类空话；每节要有结论或明确动作。
7. 不确定的信息：正文照常写，句末加 `【待确认】`；若涉及客户名称、金额、法规条款号，一律写"某三甲医院""按合同约定"或标准名称，不编造。
8. 术语首次出现给中文＋英文缩写，如"美国麻醉医师协会（ASA）分级"；之后统一用缩写。
9. 数字与单位用半角，如 `99.9%`、`< 2s`、`30 间`；中文与英文/数字之间留一个空格。
10. 输出纯 Markdown 文件到指定路径，不生成 docx，不修改其他章节文件，不修改本事实卡。

## 12. 关键写作口径（避免各章互相打架）
