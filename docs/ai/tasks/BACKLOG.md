## 每个模块的展开模板

对每个业务模块（M1–M8）依次生成并完成：

1. 契约：`packages/contracts/openapi/<域>.yaml` + 示例 + 兼容检查；
2. 数据库：`db/migration/V*` + 数据字典；
3. 后端：领域模型 → 应用服务 → 控制器 → 权限/审计 → 单测/集成测试；
4. 前端：路由/页面/表单/表格 → 契约生成类型 → 组件测试；
5. 端到端：Playwright 主流程 1 条 + 异常流程 1 条；
6. 文档：模块 README、ADR（如涉及决策）、用户手册章节；
7. 验收：对照第 2 章功能清单逐项勾选，写 `docs/acceptance/TRACEABILITY.md` 行。

## 任务卡模板（子代理简报）

```markdown
# TASK <id> <名称>
## 目标（1 句）
## 背景与依据（章节/契约/数据字典路径）
## 验收标准（Given/When/Then，≥3 条，含边界）
## 写域（允许修改的路径，白名单）
## 非目标
## 测试要求（单测/契约/E2E/覆盖率）
## 依赖（前置任务、决策、外部）
## 交付（文件清单 + 验证命令 + 结果）
```

## 执行顺序规则

1. 依赖优先：契约 → 迁移 → 后端 → 前端 → E2E；
2. 关键路径优先：M2 记录单、采集、排程冲突 > 报表/驾驶舱；
3. 每个里程碑最后一轮做集成与回归，不把缺陷留到下一里程碑；
4. 外部依赖任务先做适配器与模拟器，真实联调标 `BLOCKED-EXTERNAL`。
