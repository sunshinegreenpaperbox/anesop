# ANESOP 项目上下文（常驻）

版本 V0.9（讨论稿）· 编制日 2026-11-11 · 事实源：docs/00_事实卡与写作规范.md（v1.0）。数字冲突时以事实卡为准。

## 1. 项目一句话

ANESOP 为某三甲医院建设手术麻醉信息系统，覆盖围术期申请、排程、术前访视、术中麻醉记录、复苏、随访与管理质控全流程。定位是"临床记录系统 + 围术期管理平台"，不是排班系统，也不是科研数据库。交付形态为产品化自研 + 单院私有化，后续复制到医联体/集团医院。

## 2. 范围与边界

- 试点：1 家三甲医院，30 间手术间（含 2 间杂交/介入），年手术量约 3.5 万例。
- 一期：M0 公共支撑 + M1–M8 全量；先临床闭环（M1→M2），再管理域（M3–M7），最后驾驶舱（M8）；30 间手术间接入采集，1 个 PACU。
- 不做：AI 辅助诊断与麻醉深度预测、手术直播与远程会诊、科研数据库、互联网医院、日间手术全流程、多院区集团化平台、设备反向控制、替代 HIS/EMR/护理/SPD 核心功能。
- 边界判据：主数据谁产生谁维护（患者主索引 HIS、药品目录药房、耗材 SPD），临床记录以本系统为源、EMR 只归档；同一字段一期只允许一个权威来源。

## 4. 技术栈与架构铁律

栈：Java 21 LTS + Spring Boot 3.4 + MyBatis-Plus + Flyway + PostgreSQL 16；Vue 3.5 + TypeScript 5.6 + Element Plus + Vite；Redis 7.2、RabbitMQ 3.13、MinIO、Nginx；Docker + Compose 单院部署；设备采集为独立网关进程。

铁律：

1. 模块化单体：Maven 多模块 + 前端按模块分包；部署单元只有业务应用、采集网关、前端静态资源三个；微服务只是演进选项，不作既定方案。
2. 模块边界：每模块分 api/impl，跨模块只依赖 api；禁访问对方表或 Mapper、禁共享可变实体、禁循环依赖，由 ArchUnit 与依赖分析在 CI 检查。
3. 契约优先：OpenAPI 3.1、Flyway 迁移、领域模型先评审后编码；契约 diff 即影响面清单。
4. 采集解耦：网关断网本地缓存 ≥4 小时并幂等补传；设备只采集不控制。
5. 记录不可变：锁单后只能生成修订版本，保留原值、修改人、时间、原因。
6. 集成防腐：一个外部系统一个适配器，外部字段变化不外溢；接口失败不阻塞临床主流程。
7. 安全默认：最小权限、敏感字段加密、导出脱敏、全量审计 ≥6 个月、患者数据不出院内网络。

## 5. 工程协作规则

GitHub 是单一事实源：Issue、PR、Actions、Projects 才算事实，聊天结论不算。trunk-based，main 唯一主干，全部变更走 PR；功能分支存活 ≤3 天，修复 ≤2 天；只允许 squash merge。提交遵循 Conventional Commits 1.0.0，scope 收敛为 m0…m8、web、api、contracts、gateway、db、deploy、docs。PR 必须关联 Issue，单 PR 有效改动 ≤400 行；普通 PR 1 人批准，核心域（m2、m0 权限与审计、契约、迁移、安全）2 人批准且至少 1 名 CODEOWNERS。评审首轮 24h，核心域 12h。CI 门禁含 lint、typecheck、单测、契约、构建、SAST、依赖许可证、密钥扫描、镜像扫描、E2E 冒烟，任一失败不合并。覆盖率：整体行 ≥70%、分支 ≥55%；核心域与新增代码 ≥80%/70%；契约端点 100%。

## 6. AI 红线

AI 是产能放大器，不是责任主体；产出由人 review 并署名，代理不得进入 CODEOWNERS、不得使用 APPROVE。边界三档：脚手架、类型生成、测试、缺陷定位可代写；临床规则、权限、审计、计费、并发只出草案并人工逐行；发布、线上排障、架构决策与临床口径不得代做。六条硬红线（H-01–H-06）：患者数据不出院；不直推 main；不跳过测试；不臆造接口与字段；不引入未审批依赖；不替代临床决策。违反即停止、回滚，30 分钟内上报。含 M2 记录的发布另设准入：临床记录专项用例全过方可发布。
