# 模板：把方案转成可执行任务卡

先读（按序）：`CONTEXT_CORE.md` → `AGENTS.fragment.md` → `structured/decisions.yaml`、`structured/milestones.yaml`、`structured/sprints.yaml` → 相关章节节选。

任务：把「{{决策编号 D-xx / 功能点}}」拆成一张 GitHub Issue 任务卡，直接输出 Markdown，字段固定：

- 标题：`[{{模块 Mx}}] {{动作}}：{{对象}}`
- 目标：一句话，可验证
- 背景与上下文：引用方案书章节号（如"第 2 章 2.4.2"），列出关联决策/契约路径
- 验收标准：Given/When/Then，≥3 条，含边界条件
- 涉及范围：允许修改的目录；禁止修改的目录（契约、迁移、测试断言）
- 非目标：明确不做什么
- 测试要求：单测/契约/E2E 场景，覆盖率阈值
- 风险与回滚：数据、权限、并发、兼容性
- 依赖：前置任务、外部接口、决策是否已闭环
- AI 使用声明：工具、范围、人工复核人

约束：不得发明方案书没有的字段或接口；不确定处标【待确认】并给出需谁拍板；引用章节必须真实存在。
