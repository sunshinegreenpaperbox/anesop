# 第 5 章 AI Agents 施工约定

本章回答：人和 AI 编码代理在同一仓库里按什么规则干活、谁来签字、出事找谁。三条判断贯穿全章：AI 是产能放大器，不是责任主体；所有产出由人 review 并署名；患者安全与临床口径必须人工复核。GitHub 是单一事实源，Issue、PR、Actions 才算事实，聊天结论不算。

vibe coding 的四类事故——接口臆造、上下文漂移、测试缺失、责任稀释——分别由契约优先、上下文锚定、测试门禁、署名治理。约定自 Sprint 0（2026-11-30）生效；落地物未完成则第 6 章 AI 提效假设按 0 计。


## 5.1 定位、边界与红线


### 5.1.1 三个基本判断

AI 是产能放大器：脚手架、样板代码、测试、文档初稿、缺陷定位上替代重复劳动，提效比例见第 6 章。AI 不是责任主体：代理无署名资格，PR 的发起人与批准人承担全部责任。AI 不是黑盒：任务卡与评审记录齐全，规则可回退，账号可停用。


### 5.1.2 AI 能做什么、不能做什么

按"是否写入病历、是否改变权限边界、是否触发药品与资金流转"划三档，见表 5-1。

| 任务类型 | AI 的产出 | 人的角色 |
|---|---|---|
| 脚手架、样板代码 | 可编译骨架与测试桩 | 定分层与命名 |
| 契约到代码、类型生成 | DTO、接口桩、生成类型 | 评审契约本身 |
| 单测、契约测试、E2E | 用例与测试代码 | 审断言是否验证行为 |
| 缺陷定位、日志分析 | 根因假设、复现命令 | 定根因与修复方案 |
| 临床规则、评分、阈值 | 仅骨架与配置项 | 顾问定口径，人逐行 |
| 权限、审计、计费、并发 | 草案与风险清单 | 逐行复核并署名 |
| 线上排障、发布、架构决策 | 无（只做只读分析） | 人执行决策 |

### 5.1.3 六条硬红线

红线是最高优先级规则，人指挥代理触碰同样算违规，见表 5-2。

| 编号 | 红线 | 检查与处置 |
|---|---|---|
| H-01 | 患者数据不出院：不进外部大模型、SaaS、公网问答 | 出网白名单、脱敏评审、网关日志；违反即停止并 30 分钟内上报 |
| H-02 | 不直推 main：变更走 PR | 分支保护 + checks + CODEOWNERS；违反即回滚、撤权 |
| H-03 | 不跳过测试：不删测试、不降门槛 | 覆盖率对比、删除检测；违反即拒合计入返工 |
| H-04 | 不臆造接口与字段：只引用已评审契约 | 契约对拍、类型检查；违反即拒合 |
| H-05 | 不引入未审批依赖：白名单外需 ADR | lockfile diff、许可证扫描；违反即移除并补批 |
| H-06 | 不替代临床决策：不改临床口径、不代签 | 顾问签字、CODEOWNERS、E2E；违反即回退并回写 |

表 5-2 六条硬红线

三层执行缺一不可：机器可拦（H-02、H-03、H-05）、流程可查（H-04、H-01）、人工判定（H-06）。红线不因进度紧豁免，S4 春节低产能期同样适用。


### 5.1.4 责任归属与人 review 署名

每个 PR 记录两类人：提交发起人（可代发起任务）与批准人（CODEOWNERS 自然人）。机器人账号不得进入 CODEOWNERS，不得使用 APPROVE。PR 模板（§4.6.1）必填 AI 声明（工具、版本、范围、复核人）；高风险文件（5.7.2）单次生成超过 50 行须加 trailer，字段沿用 §4.5.2 的五个：AI-Tool、AI-Task、AI-Scope、Reviewed-by、Co-authored-by。

署名原则是"谁批准谁负责"：批准人须说明核对了什么，评审记录与审计日志保存期一致（≥6 个月）。AI 风险已在 §4.11 的 R-06 登记。Sprint 0 落地五件：根 AGENTS.md、PR 模板 AI 声明栏、ai-task.yml、usage-log 登记表、出网白名单；责任人为 AI 工程支持，纳入 M1 验收。


## 5.2 规则文件体系


### 5.2.1 设计原则

单一主文件、薄适配层：规则正文只写 AGENTS.md 与模块 AGENTS.md，工具文件只做入口映射；多套规则各写一份，代理会挑有利的执行。规则即代码：同仓、同 PR（§4.6）、同 CI（§4.7）、可回滚。就近生效：根写全局、子目录写细节，最近者优先。能机器查的不写"请注意"，每条规则配脚本、CI 或 PR 勾选项。

# AGENTS.md — ANESOP 仓库级施工总纲（v1.0，2026-11-11）
 
## 0. 地位与优先级
本文件是 AI 代理在本仓库的唯一规则入口；CLAUDE.md、.cursor/rules、

## 1. 每次任务先读（按序，最多 6 项）
1) 任务卡 docs/ai/tasks/TASK-<issue>.md

3) 模块规则 docs/modules/<域>/AGENTS.md
4) 契约 packages/contracts/openapi/<域>.yaml
5) 任务卡"上下文索引"列出的 ADR

## 2. 技术栈锁定（新增走 ADR + 白名单）
Java 21 / Spring Boot 3.4 / MyBatis-Plus + Flyway / PostgreSQL 16；
Vue 3.5 + TypeScript 5.6 / Element Plus / Vite；springdoc-openapi 2.x。
 
## 3. 常用命令（改完必须自己跑）
mvn -B verify；pnpm lint；pnpm test:unit；pnpm e2e；
./scripts/check-rules.sh
 
## 4. 红线（违反即停止并上报）
H-01 患者数据不出院；H-02 不直推 main；H-03 不跳过测试；
H-04 不臆造接口与字段；H-05 不引入未审批依赖；H-06 不替代临床决策。
 
## 5. 提交前自检（缺一不可）
编译与类型检查通过；新增行为有测试且断言有效；无未审批依赖；契约未私改；

### 5.2.6 适配层生成与漂移检查

适配层不手写，由 scripts/gen-agent-adapters.mjs 生成，用 gen:begin/gen:end 标记；标记外只允许入口语法、路径映射（Cursor 的 globs、Copilot 的 applyTo）、平台限制说明三类内容。check-rules.sh 重新生成并 diff，不一致即失败；适配层不写补充规则；工具升级后 1 周内复核。


### 5.2.7 版本管理、变更评审与失效清理

规则文件头部写版本与变更链接；红线或技术栈变更升 major，新增条款升 minor，措辞修正升 patch。规则 PR 打 type/doc，需架构师与 AI 工程支持双人批准，涉临床加签临床顾问，涉安全加签安全负责人，与代码 PR 分开。临时条款须写 失效日期：YYYY-MM-DD，check-rules.sh 扫描过期并使 CI 失败；连续两季度零引用降级或删除。复评触发：红线违规、同类缺陷复发、工具升级、监管口径变化。


## 5.3 多智能体角色与分工

代理角色是"权限 + 上下文 + 交接物格式"的组合，不是人格设定；一次任务只能有一个写入角色，避免两个代理同时改同一文件。如图 5-1 所示，协作分四层：编排层拆解分派，角色层在受限写域内产出，评审门禁层收敛，事实层由 GitHub 记录。

### 5.3.2 三种人机协同模式

按规模与耦合度选模式，选错比不用 AI 更费时间，见表 5-6。

| 模式 | 适用任务 | 隔离方式 | 主要风险与对策 |
|---|---|---|---|
| A 单人 + 代理 | ≤2 人日、单模块、无契约变更 | 1 人 + 1 代理，同一副本 | 过度信任；自检清单 + 抽检 30% |
| B 双人结对 + 代理 | 3–8 人日、跨前后端或含契约变更 | 2 人（主写 + 复核）+ 1–2 代理 | 职责稀释；谁批准谁负责 |
| C 并行多代理 | ≥8 人日、可切分为写域不重叠的子任务 | 3–5 代理，各自分支与上下文 | 冲突与重复实现；先冻结契约与文件清单 |

表 5-6 三种人机协同模式

模式 C 硬约束：同一契约、迁移序号、组件文件不得两个代理并行改；确需并行先拆接口。代理"讨论"不产生决策，决策落任务卡或 ADR。


### 5.3.3 何时必须人工介入

出现以下任一情形，立即停止代理并转人工，结论落记录：

• 临床规则、评分公式、预警阈值、核查项与知情同意文本；

• 权限模型、数据范围、审计字段、签名与留痕；

• 事务与并发、锁单修订、库存与麻精药品扣减；

• 计费、对账、DRG/DIP 口径；

• 不可逆迁移、历史数据清洗、对外接口报文；

• 认证、加密、脱敏、导出与日志；

• 上线、回滚与生产变更；

• 代理连续两轮验证失败，或必须改契约与规则才能继续。

人工介入指打开 diff 逐行阅读并署名，不是"看一眼聊天记录点通过"。


### 5.3.4 反模式

代理套娃、全仓库塞进一个上下文、自证闭环（同一代理既写又审）、以"AI 说可以"为证据、让代理决定范围。出现即停，按 5.7.3 复盘。

## 5.5 上下文工程

代理能力上限由上下文决定。上下文工程不是多给资料，而是给对的文件、版本与范围：给得越多，噪声越大，过期信息越容易压过最新事实。


### 5.5.1 上下文分层与预算

预算按行数控制，token 按窗口折算，窗口在选型后写入附录【待确认】：L0 ≤300 行、L1 ≤200 行加按需契约、L2 ≤120 行、L3 ≤窗口 60%。超预算先删 L3，再压 L1；不许删 L0 红线与 L2 验收标准，仍超就拆任务。单文件超过 800 行按符号检索分段读。


### 5.5.2 repo map 与模块 README

repo-map.md 由 scripts/gen-repo-map.sh 生成，每模块一行：模块号、名称、后端包、前端目录、入口、契约、测试目录、负责人；未更新时 CI 失败。模块 README 六节：边界、数据归属、接口、依赖与事件、关键流程、变更记录。README 说"模块是什么"，AGENTS.md 说"代理怎么做、禁止什么"。


### 5.5.3 术语表、契约与数据字典

glossary.md 每条含术语、英文或缩写、定义、来源（WS 445、国家麻醉质控指标、院方口径）、易混词、禁用同义词；首期不少于 200 条，临床顾问签核生效。代理必须用术语表写法，如统一"麻醉记录单"、首次写"复苏室（PACU）"，不一致即退回。提示词禁止复制字段清单，一律引用契约与数据字典：契约用 packages/contracts/openapi/<域>.yaml@<sha>，数据字典用 docs/data-dictionary/<域>.md，每字段写表、字段名、类型、枚举、敏感标识、来源、变更历史。契约与字典属 L1，变更走评审并触发任务卡重读，代理在 PR 声明契约 sha。

### 5.5.5 few-shot 示例库与禁止凭记忆写 API

docs/ai/examples/ 每类留一个黄金样例：backend-controller.md、flyway-migration.md、vue-form.md、playwright-spec.md、security-check.md，头部声明契约与规则版本；只放结构与约定，含患者信息的示例禁止入库，契约升级后标 stale。禁止凭记忆写 API：依赖走白名单 scripts/dependency-allowlist.txt；外部调用给文档链接或契约路径；编译与类型检查作第一道验证；CI 用 springdoc 结果与契约对拍；前端类型由 pnpm gen:api 生成且禁止手改；评审固定一问"外部调用能否指到契约或文档"。


### 5.5.6 上下文污染与过期处理

污染来源五类：过期契约、废弃 ADR、旧示例、失败日志、未合并分支代码。处理：任务卡索引带版本或 sha，代理输出首行声明版本；契约、迁移或规则变更时 CI 给相关 PR 打 ctx-stale，带标签不得合并，除非重读并更新 handoff；连续两轮失败或上下文占窗口 80% 时停止会话，用 handoff 重建；失败日志只留结论与报错摘要，含患者信息的日志禁止进入模型。

## 5.6 契约优先与测试要求

契约是人与代理的共同真相，测试是 AI 产出唯一可信的完成证据；没有契约代理会发明字段，没有测试"完成"只是聊天记录。通用测试见 §4.9，本节只写 AI 增补。


### 5.6.1 契约先行评审

每个业务域先评审三件套，顺序固定：领域模型（实体、枚举、状态机）、迁移（Flyway）、OpenAPI 3.1 契约。架构师必审，涉临床加顾问，涉外部系统加集成工程师；PR 含契约 diff、兼容性说明（新增/可选/破坏性）、迁移回滚记录。字段只增不删，删除或改类型必须升 major、双写过渡并写 ADR（§4.8）。Sprint 第 3 个工作日后契约冻结，阻断缺陷除外。


### 5.6.2 前端类型由契约生成

apps/web/src/api/generated/ 由契约生成，禁止手写手改；扩展类型先改契约再生成。联调用契约生成的 mock（如 MSW），不进生产构建。契约变更时类型 diff 就是影响面清单，typecheck 失败不允许合并。

### 5.7.3 AI Review 与缺陷复盘回写

AI 评审是初审不是结论：只在 PR 留 COMMENT，不产生 APPROVE；合并只认 CODEOWNERS 自然人批准。输入 diff、契约、规则与风险清单，自检结论只作参考；输出分阻断、建议、提问三级，带 文件:行号；人工决定采纳，误报率超过 30% 的提示词需修订；同一代理不得既写又审，AI 不得写审批记录。

缺陷复盘触发：P1/P2 缺陷、红线事件、同类缺陷第二次出现；记录缺陷 ID、发现阶段、根因、AI 参与环节、直接原因、规则缺口与动作、验证方式、责任人、期限。根因七类：需求、契约、实现、测试、规则缺失、上下文过期、评审失效。动作必须可执行：改哪条规则、加哪个检查、加哪个测试、改哪个提示词。规则 PR 与修复 PR 分开；两次未回写即流程失效。

## 5.9 数据合规与安全


### 5.9.1 患者数据红线与脱敏

A-09 是硬约束：AI 工具只用于研发，患者数据不得进入外部大模型，生产环境不调用外部模型。"脱敏三问"任一不过就改用合成数据或只给结构：是否含直接标识（姓名、身份证、住院号、手机、人脸）；能否组合重识别（年龄 + 精确日期 + 罕见术式）；是否必要、能否用字段名替代。分级见表 5-18。

| 数据类别 | 示例 | 可否进入外部模型 | 允许方式 |
|---|---|---|---|
| 直接标识符 | 姓名、身份证、住院号、手机、人脸 | 禁止 | 合成值：患者 A、编号 P-0001 |
| 准标识符组合 | 年龄 + 精确日期 + 科室 + 罕见术式 | 禁止原始组合 | 泛化为年龄段、季度 |
| 临床自由文本 | 麻醉记录描述、病程记录 | 禁止原文 | 只给字段名与结构，必要时人工脱敏 |
| 检验与生命体征 | 血气、血压、心率 | 条件允许 | 与患者标识断开，时间粗化到日 |
| 代码与报错 | 异常栈、SQL 报错 | 允许 | 删除参数值、token、真实 SQL 实参 |
| 架构与契约 | 表结构、OpenAPI、字段名 | 允许 | 无额外限制 |

### 5.9.2 模型与账号管理

统一要求：企业版或私有化部署，调用经院内网关，禁止直连；账号实名、SSO，禁止个人账号处理代码；生产网段禁止访问外部模型 API，出网白名单；网关记录账号、时间、任务 ID、prompt 摘要，留存 ≥6 个月；离职转岗当日禁用；使用登记写入 docs/ai/usage-log/YYYY-MM.md，字段为日期、任务 ID、工具与版本、工号、范围、产出、复核人，不得含患者信息与 prompt 原文。


### 5.9.3 供应商条款与知识产权

合同须覆盖：数据不用于训练；零保留或明确期限；数据驻留与跨境；代码与产出归属；生成内容责任；审计报告权；子处理者披露；终止后删除。生成代码知识产权按合同归项目或客户【待确认】。执行：不粘贴来源不明代码；依赖许可证走白名单（MIT、Apache-2.0、BSD 允许，GPL/AGPL 禁止进入交付物，LGPL 待法务评估【待确认】）；新增依赖附许可证结论。检查用 mvn license:add-third-party、pnpm licenses list 与 GitHub 依赖审查。


### 5.9.4 审计留痕与事件处置

留痕五类：AI 任务登记（任务、工具、账号、产出、复核人）、提交声明（五个 trailer）、评审记录（评审人、结论、逐行）、网关日志、数据外发审批。目标是"可复核"，不是记录所有 prompt；敏感 prompt 禁止落库。一级事件（疑似患者数据进入外部模型）30 分钟内上报信息安全负责人与项目经理，2 小时内隔离账号或网关并留证，24 小时内交报告，按院方预案执行【待确认流程】，并进入 5.7.3 复盘回写。
