# 大屏与驾驶舱培训（手术室/院领导查看）

> 目标：会打开、投屏、切换实时看板与风险大屏，能判断"数据停更/权限不足/网络异常"，
> 知道异常时找谁。
> 权限：`m5:dashboard:read`（SYS_ADMIN/SYS_OR_MANAGER/SYS_ANESTHESIOLOGIST/SYS_QC_MANAGER）；
> 数据范围按角色（DEPT/ALL），**看板只展示台次状态/计数，不展示患者身份信息**。

## 1. 入口与布局

1. 登录后左侧"实时看板"（`/m5/dashboard`）：术间状态、台次进度、告警、资源/KPI；
2. "风险与资源大屏"（`/m5/dashboard/risk`）：风险分层、利用率、告警趋势、人员/设备资源；
3. 页面每 **10 秒**轮询一次（非 SSE）；右上角可"暂停/继续/立即刷新";
4. 大屏模式：浏览器全屏（F11），隐藏地址栏；建议 1920×1080 及以上、暗色环境。

## 2. 日常使用

1. 每班开始打开看板，确认"更新时间"在 10–30 秒内；
2. 查看术间状态（空闲/准备/麻醉/手术/复苏/清洁）与超时台次；
3. 告警区按级别处理：P1 立即电话、P2 企业微信、P3 邮件（以院方配置为准）；
4. 需要细节时点台次跳转（有权限才可打开记录/排程）；大屏本身不显示 PHI；
5. 交接班时口头说明未闭环告警与超时台次。

## 3. 数据口径与限制

- KPI/利用率默认口径见 `docs/modules/m5/README.md` 与 ADR-0023（【待确认】项以院方最终口径为准）；
- 看板为**运营视图**，不作为临床决策或绩效结算的唯一依据；
- 数据范围裁剪后数字变小是正常现象；跨科室查看需授权；
- 看板不做导出；需要报表去"工作量报表/质控指标"。

## 4. 常见错误与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面空白/转圈 | API 不可用/网络断/会话过期 | 刷新；仍空白按 runbook 报障；必要时用报表兜底 |
| 数字长时间不变 | 轮询被暂停/浏览器休眠/网络断 | 点"继续/立即刷新"；检查网络与终端电源策略 |
| 403/菜单不可见 | 无 `m5:dashboard:read` 或范围为空 | 找管理员授权；不要共用管理员账号 |
| 数字与报表不一致 | 口径/时间窗/数据范围不同 | 对照口径与时间窗；记录差异交质控/信息科 |
| 大屏字体过小/截断 | 分辨率/缩放不匹配 | 浏览器 100% 缩放、全屏、调整分辨率 |
| 时间显示异常 | 终端时区/NTP 不对 | 终端设 Asia/Shanghai 并同步 NTP |
| 告警闪烁但无详情 | 大屏不展示 PHI/详情 | 到有权限的页面查看；不要在大屏展示患者信息 |

## 5. 大屏运维建议

- 使用专用账号（只读看板）+ 专用终端，禁止登录管理员账号；
- 终端关闭自动更新/屏保，配置开机自启浏览器与看板 URL；
- 网络走院内有线/稳定 Wi-Fi；断网时看板不可用属预期，临床记录不受影响（本地记录继续）；
- 每周检查一次更新时间与告警通道；发现长期停更按 P1/P2 报障；
- 大屏拍照/录屏不得包含患者信息（本看板设计上不含）。

## 6. 考核（2 项）

1. 打开两个看板并说出 3 个 KPI/风险指标含义；
2. 模拟"数据停更"，按步骤判断是暂停、网络还是会话问题并上报。
